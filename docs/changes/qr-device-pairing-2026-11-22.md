## 사용자 문제와 완료 조건

### 현재 동작과 문제
- ottline은 무로그인·로컬 우선 방식으로 Web/PWA, Windows, macOS, iPad, iPhone, Android에서 같은 타임라인을 이어 쓴다.
- 현재 다른 기기를 연결하려면 `내 공간`에서 8자리 연결 코드를 확인한 뒤 새 기기에 직접 입력해야 한다(또는 데스크톱/TWA 업그레이드 경로에서 브라우저 이어받기 사용).
- PC·웹·태블릿에서 기록을 쓰던 사용자가 폰 앱을 설치해 연결하려는 순간, 8자리 코드를 보고 수동 입력하는 마찰 때문에 두 번째 기기 연결을 미루거나 포기하기 쉽다.
- 기존 [페어링 코드 복구 카드](../pairing-recovery-card.md)에서도 QR 스캔 연결은 후속 검토 과제로 남겨둔 상태다.

### 기대하는 사용자 경험 (핵심 시나리오)
1. **주 시나리오 (큰 화면 → 모바일/태블릿 즉시 연결)**:
   - 기존 기기(Web/Windows/macOS/iPad 등)의 `내 공간 > 기기 연결`에서 `QR로 다른 기기 연결`을 누른다.
   - 짧은 유효 시간이 표시된 연결용 QR이 화면에 나타난다(원할 때 취소·재발급 가능).
   - 새 기기(iPhone/iPad/Android)에서 QR을 스캔하면 연결 대상 안내와 확인 단계가 표시되고, 사용자가 확인하면 바로 같은 타임라인이 이어진다.
2. **기존 연결 코드·복구 카드와의 역할 분리**:
   - QR은 기존 **8자리 연결 코드 입력**과 **영구 보관용 복구 카드 PNG**를 대체하지 않고 **보완**한다.
   - 폰 → PC 방향 연결, 카메라가 없거나 권한을 거부한 환경, 기기 분실·교체 시에는 기존 8자리 코드 입력과 복구 카드를 그대로 사용한다.

### 완료 조건 (기획 인수 기준)
1. 빈 새 기기에서 큰 화면의 연결 QR을 스캔해 확인하면 기존 계정의 타임라인이 누락 없이 이어진다.
2. 이미 로컬 기록이 있는 새 기기에서 스캔할 때 자동 병합하지 않고 **"이 기기의 기록 N건이 연결 계정과 합쳐집니다"** 확인/취소 안내를 거쳐 진행하며, 취소 시 양쪽 데이터 변화가 없다.
3. 연결용 QR은 상시 노출되지 않고 사용자 요청 시에만 표시되며, 짧은 시간이 지나면 만료되고 1회 연결 후 즉시 무효화된다. 사용자가 원할 때 수동 취소·재발급할 수 있다.
4. 만료된 QR, 이미 사용된 QR, 오프라인 상태, 카메라 권한 거부 상황에서 명확한 KO/EN 안내와 함께 기존 8자리 코드 입력으로 자연스럽게 전환할 수 있다.
5. 기존 설치된 구형 앱의 8자리 코드 입력·복구 카드·동기화 흐름이 깨지지 않는다.

## 공통 목표와 플랫폼 차이

- **관련 기능 기준표 항목**([feature-matrix.md](../feature-matrix.md)): `3. 계정·기기 연결`, `9. 기기 표기·계측`, `10. 언어·접근성·상태 안내`.
- **공통 유지 결과**: QR 연결로 합류한 기기도 기존 코드 연결과 동일한 계정·기기 목록·동기화·프로필 규칙을 따르며, 연결 기기 목록에 기기 유형이 정상 표시된다.

| 대상 | 목표 지원 범위 | 기대 경험 |
| --- | --- | --- |
| **Web/PWA · Windows · macOS** | **공통 필수(QR 표시)** / 선택·후순위(스캔) | `내 공간`에서 연결용 QR 표시·취소·재발급. 새 기기 연결은 기존 8자리 코드 입력 유지. |
| **iPhone · iPad · Android** | **공통 필수(QR 표시 + 스캔)** | `내 공간`에서 연결용 QR 표시 및 카메라 스캔으로 빠른 기기 연결. 카메라 거부 시 코드 입력 전환. |
| **Chrome·Edge·Whale 확장 · 토스 인앱 · ChatGPT 앱** | **명시적 미지원** | 보조 진입·별도 채널 역할 범위 밖(기존 연결 방식 유지). |

## 제품 정책과 안전 기준 (기획 요구사항)

1. **기본 비노출 & 요청 시 표시**: 설정 화면을 열자마자 QR이 노출되어 타인이 촬영하는 일을 막기 위해, `QR로 다른 기기 연결` 버튼을 눌렀을 때만 QR을 표시한다.
2. **단기 만료 · 1회성 · 취소/재발급**: 화면 캡처나 어깨너머 촬영으로 영구 접근 권한이 유출되지 않도록, QR은 짧은 유효 시간 후 자동 만료되고 1회 사용 후 무효화되며 표시 화면에서 즉시 닫기(취소)·새로 고침(재발급)할 수 있어야 한다.
3. **영구 복구 카드와 철저히 분리**: 개인 보관용 복구 카드 PNG는 기기 분실 대비용이므로, 실시간 기기 연결용 QR과 섞지 않는다(사진첩 공유·클라우드 노출 시 즉시 계정 탈취 위험 차단).
4. **프라이버시 고지 (KO/EN)**: QR 표시 화면에 "내 다른 기기를 연결할 때만 사용하세요. 다른 사람에게 공유하지 마세요." 수준의 짧고 분명한 안내를 포함한다.
5. **명시적 병합 동의**: 새 기기에 로컬 기록이 존재하면 스캔만으로 자동 병합하지 않고 기록 건수 안내 후 사용자 확인을 받는다.
6. **실패·오프라인·권한 거부 복구력**:
   - 표시 측 또는 스캔 측이 오프라인이면 오프라인 안내와 재시도 또는 기존 코드 연결 안내를 보여준다.
   - 카메라 권한을 거부하면 설정 이동 안내와 함께 즉시 8자리 코드 입력 칸으로 전환한다.
   - 만료·이미 사용된 QR 스캔 시 "코드가 만료되었어요. 기존 기기에서 새 QR을 열어 주세요."처럼 행동 가능한 안내를 제공한다.

## API·플랫폼 담당 기술 검토 요청 항목 (착수 전 선행 관문)

본부 판단([#165 댓글](https://github.com/chawon/ott/issues/165#issuecomment-7076933417))에 따라 구현 전 아래 항목을 API·플랫폼 담당과 검토해 기술 설계를 확정한다:

1. **만료·1회성·재발급/취소·동시 스캔 보호**: 영구 페어링 코드를 QR에 그대로 넣지 않고 단기·1회용 연결을 보장하는 방식, 짧은 유효 시간 기준, 동시 스캔 시 선점·거절 처리.
2. **스캔 진입 경로와 로그/URL 노출 차단**: 앱 내 카메라 스캐너 전용 방식 vs OS 기본 카메라 스캔(딥링크)의 장단점과, 어떤 경우에도 영구 코드나 민감 식별자가 브라우저 방문기록·서버 로그·analytics 경로에 남지 않도록 하는 경계.
3. **이미 기록이 있는 기기의 병합 안전성 & 구형 앱 호환**: 기존 계정 병합 계약(기록·이력·추천 상태·제외 목록 보존)과의 일치 및 구형 앱의 코드 연결 영향 없음 확인.
4. **연결 계측 정합성 ([`#169`](https://github.com/chawon/ott/issues/169) 연계)**: 코드 페어링·자동 이어받기·QR 연결의 시도/성공/실패와 실패 분류(만료·취소·권한거부·오프라인)를 `#169` 공통 계측 계약에 중복 없이 통합 정의. 가입(`register`)과 연결 성공을 혼동하지 않음.
