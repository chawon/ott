## 3. 다음 사이클 개선 후보 3개 및 추천 순서

신규 기능만 늘리지 않고 **① 확인된 데이터 신뢰·계정 삭제 안전성 결함 복구(확정 우선) → ② 반복 기록 회상 가치 검증(가설) → ③ 안심 연결·다중 기기·`함께` 자생 루프 검증(가설)** 순으로 제안한다.

### 1순위 (우선 방향 합의 · 변경안 초안 제출): 멀티 기기 동기화·계정 삭제 안전성 복구

- **사용자 문제**: `#157` 1차 감사(`4db7be6` 기준)에서 다중 기기 기록 보존과 삭제 안전성을 직접 해치는 클라이언트 결함 3건이 확인됐다.
  1. **Windows (`#161`)**: `main` `4db7be6`에서도 기록 업로드(`sync/push`) 계약 불일치로 서버에 반영되지 않고 outbox가 삭제·`synced` 오표기되는 결함이 남아 있다. 새 기록의 정상 업로드뿐 아니라 **이전 설치판(`2.0.0.0`/`2.0.1.0`)에서 이미 누락·오표기된 기존 기록의 안전한 회복**이 필수다. *(큐레이터 제거·함께 2단·`PUT /reactions`·추천 복구는 `#156`으로 병합 완료, Store `2.0.2.0` 확인 대기.)*
  2. **Web/PWA (`#162`)**: 충돌(`stale`) 거절 시 해당 충돌 기록의 서버 최신 상태와 대상 작업의 해소를 검증하지 못한 채 outbox가 남아 후속 동기화를 막을 수 있다.
  3. **iOS / iPadOS / macOS (`#163`, `2.0.1`)**: 서버 계정 삭제 실패 시 로컬 데이터는 남지만 화면이 성공 안내를 잘못 표시한다.
- **근거 출처·시점**: `#157` 코드 감사(`2026-11-22`, `main` `4db7be6`). 실제 운영 발생 건수는 `미측정`(무음 실패 구조로 기존 통계에서 포착 불가).
- **기대 효과**: 다중 기기 동기화와 삭제 안전성에 대한 신뢰 이탈을 선제 차단해 2·3순위 반복 이용·연결 개선의 전제 조건을 확보한다.
- **성공 지표 및 검증 기준**:
  - **QA 인수 기준**: Windows 전송 대상 **로그 ID별 서버 반영 및 타 기기 정식 기록 확인 `100%`** + 기존 설치판 업그레이드 후 누락 기록 회복·중단 재개 시 중복/덮어쓰기 `0건`; Web `stale` 충돌 5대 안전 시나리오 유실 `0건`; Apple 삭제 실패 시 오류·재시도 안내 `100%`.
  - **운영 관찰 지표 (배포 후 완료된 14일 KST)**: Windows 정상 동기화 활동 확인 및 2대 이상 기기 실제 기록·동기화 계정 추이(데이터 출처·기기 귀속 집계 정의를 운영·API 담당과 확정 후 측정, 현재 기준선 `미측정`).
- **영향 플랫폼 / 제외 범위**: Windows(`#161`, `2.0.2.0`), Web/PWA(`#162`), iOS/iPadOS/macOS(`#163`, `2.0.1`). API 스키마 변경 없음(이력 권한 경계는 본부 독립 API 검증 업무로 분리). Android·확장·토스·ChatGPT 제외.
- **상세 변경안 초안**: [cross-platform-sync-and-contract-reliability-2026-11-22.md](cross-platform-sync-and-contract-reliability-2026-11-22.md)

### 2순위 (검증할 가설 · 기준선 보완 후 확정): 포스터/표지 기반 '월간 기록 달력' + 저부담 회상 카드

- **사용자 문제와 가설**: `#157` 감사 기준 ottline 전 플랫폼에는 월간 달력 뷰가 없으며 타임라인이 리스트 중심이다. `#159` 리서치에서 복수 기록 앱(북모리·레포브 등)이 월간 달력·시간 기반 회상을 제공하는 점을 관찰했으며, **영상+책 포스터/표지가 함께 쌓이는 월간 달력 및 과거 기록 회상**이 죄책감 없는 재방문 동기를 만들어 2~4주차 반복 기록을 높일 것이라는 **가설**을 세운다.
- **근거·기준선**: 현재 2~4주차 반복 기록 코호트는 `미측정`(본부 요청 중). 기준선 확보 및 1순위 복구 이후 착수 여부를 확정한다.
- **기대 효과 (가설)**: 2~4주차 반복 기록 개선 및 월간 달력 공유 카드를 통한 자발적 공유·유입([marketing-operations.md](../marketing-operations.md)) 연계.
- **성공 지표 및 검증 설계 (자기 선택 편향 분리)**:
  - 달력 조회자와 비조회자의 단순 비교는 원래 열심히 기록하는 사용자가 달력을 더 많이 여는 **자기 선택 편향**이 크므로 효과 입증 대조군으로 사용하지 않는다.
  - **탐색 지표**: `calendar_open` 도달 actor / `qualifiedActors`, 월간 공유 카드 생성 수 (데이터 출처: analytics 이벤트, 수집 담당: Web/API 담당과 허용 이벤트 정의 필요).
  - **효과 검증**: 도입 전후 동일 기준(관리자 제외, 완료된 주간 코호트) 비교 또는 제한 노출 실험으로 2~4주차 재기록 변화 확인.
- **영향 플랫폼 / 제외 범위**: 1단계 Web/PWA 우선 검증(기존 기록 날짜·포스터 데이터 활용, 선행 API 스키마 변경 없음) → 효과 확인 후 네이티브 확산. 확장·토스·ChatGPT 제외.
- **되돌림 조건**: 기존 리스트 타임라인과 전환 토글로 제공해 기존 흐름 비파괴; 4주 관찰 후 활용도 저조 시 토글 제거.

### 3순위 (검증할 가설 · `#165` QR 기획 연계): 첫 기록 이후 안심 연결(복구·QR 기기 연결) & `SavedDiscussionLink` 일관화

- **사용자 문제와 가설**:
  1. 무로그인·로컬 우선 구조에서 초기 기록을 남긴 사용자가 "기기 교체 시 기록 유실" 불안 없이 2번째 기기로 자연스럽게 연결되도록 돕는 장치가 약하다. 초기 기록 이후 복구 카드 보관 안내와 **[#165 QR 코드 기기 연결](https://github.com/chawon/ott/issues/165)**을 결합하면 2번째 기기 연결 마찰을 크게 줄일 수 있다는 **가설**을 검증한다. *(안내 노출 기준 건수 — 예: 1~3건 — 은 확정 사실이 아닌 실험 가설이다.)*
  2. 큐레이터 종료 이후 `함께`의 자생 동력인 **저장 뒤 같은 작품 공개 이야기 연결(`/discussions/connection`)**이 Web·Apple에만 반영돼 있고 Android·Windows에는 빠져 있다.
  3. Mac 스토어 설치판 검증(`313827720`) 완료 후 Web의 확장 빠른 기록 브리지를 macOS까지 확대한다.
- **근거·기준선**: 다중 기기 실사용률 및 페어링 시도/성공률은 `미측정`(계측 공백 포함, 본부 요청 중).
- **`#165` QR 코드 기기 연결 연계 범위 및 선행 검토**:
  - **연계 시점**: 1순위(`#161`~`#163`) 동기화 신뢰 복구 및 본부 기준선 확보 이후, 3순위 안심 연결 묶음과 함께 착수 검토.
  - **기획 범위**: 큰 화면(Web/Windows/macOS/iPad) → 모바일/태블릿(iOS/Android) 즉시 연결, 필요 시에만 노출·단기/1회성 원칙·복구 카드 분리·기존 기록 명시적 병합 동의([#165](https://github.com/chawon/ott/issues/165)).
  - **필요한 API·플랫폼 기술 검토**: 단기 1회용 연결 방식(만료·소진·보안), 카메라 스캔 진입 방식, 기존 코드 페어링과의 공존 및 계측 이벤트 설계는 API·플랫폼 담당 검토 후 변경안을 확정한다.
- **성공 지표 (분자/분모)**:
  - 연결 시도(코드·QR·안심 카드) 대비 연결 완료 비율 (신규 계측 정의 필요, 현재 `미측정`).
