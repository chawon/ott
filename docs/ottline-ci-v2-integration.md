# ottline CI v2 통합

## 범위와 방향

2026-11-04 사용자가 CI도 대규모 개편 범위에 포함하고 앱 아이콘으로 함께 쓰도록 승인했다. 기존 열린 책·재생 심벌을 바탕으로 곡선·획·여백을 정리한 A를 권장안으로 삼고, 시간 경로를 탐색한 B는 비교 시안으로 둔다. 크림 `#F8F6F2`, 네이비 `#1E4D8C`, 주황 `#FF9933`을 사용한다. 이름은 기존 Pretendard의 글자 모양과 자간을 유지한다.

2026-11-05 사용자가 기존의 글자체와 간격이 좋다는 교정을 주었다. 최종 웹 헤더는 원래와 같은 Pretendard Bold, 30px/36px, 700, 자간 -0.025em으로 복원한다. 부제도 9px, 600, 자간 0.1em으로 원복한다. 새 기하학 글자를 더 굵게 만드는 방식은 사용하지 않는다. 심벌·팔레트·앱 아이콘 원형은 유지한다.

## 통합 원칙

- SVG 마스터와 내보내기 자산은 `apps/web/public/brand/v2/`에 버전별로 보관한다.
- 실제 웹 헤더에는 심벌·워드마크·부제를 함께 쓴다. 워드마크는 기존 서체를 직접 렌더하고 심벌은 밝은/어두운 배경용을 구분한다. 작은 모바일에서도 메뉴·언어·테마 버튼과 겹치지 않게 한다.
- PWA·웹 메타데이터는 새 버전 경로를 사용한다. 기존 `/icon.png` 등은 현재 네이티브/TWA 릴리스의 해시 검증과 연결되어 있어 이번 시안 통합에서 덮어쓰지 않는다.
- iOS용 불투명 정사각 PNG와 Android adaptive·단색 레이어를 같은 마스터에서 준비한다. 설치된 네이티브 앱·스토어 아이콘의 변경에는 별도 바이너리/스토어 배포가 필요하며 이번 작업은 디자인·로컬 웹 미리보기·내보내기 자산 범위다.
- 디자인 비교 페이지에서 기존 CI와 A/B, 실제 헤더 크기, 작은 아이콘, 원형·둥근 사각형 마스크를 비교할 수 있게 한다.

## 검증 기준

16·24·32·48·64px 축소 형태와 1024px 원본을 확인한다. 앱 아이콘 배경은 불투명한 전체 정사각형이며 모서리는 시스템 마스크로 처리한다. Android 108dp 레이어의 핵심 그림을 중앙 66dp 영역 안에, PWA maskable 그림을 중앙 반지름 40% 원 안에 배치한다. 실제 픽셀 경계와 알파를 검사하고 웹 헤더는 KO/EN·PC/모바일·라이트/다크에서 확인한다.

플랫폼 기준은 [Apple App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons/), [Android Adaptive icons](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive), [W3C maskable 안전 영역](https://www.w3.org/TR/appmanifest/#icon-masks-and-safe-zone)을 참고했다. `.icon`/Icon Composer 프로젝트를 만든 것으로 표현하지 않으며, 레이어 원본을 제공한다.

## 최종 적용과 검증 (2026-11-05)

- 실제 웹 헤더는 새 심벌과 **기존 Pretendard 글자체·굵기·자간**을 조합한다. CI 벡터의 글자도 같은 로컬 폰트에서 추출한 윤곽으로 맞췄다. 서체의 출처·해시와 재추출 방법은 [CI 자산 문서](ottline-ci-v2.md)에 있다.
- 파비콘, PWA 아이콘, 사이트 OG/Twitter 이미지와 웹 앱·조직 구조화 데이터의 CI 경로를 연결했다. 기존 TWA와 결합된 `/icon.png`는 보존했고, TWA 원본 자산 7개 해시 검사를 통과했다. 브라우저 확장·네이티브 바이너리·스토어 배포는 수행하지 않았다.
- 실제 개발 데이터를 읽은 새 방문자 화면으로 가이드 이미지 6장(2560×1600), 한·영 PWA 설치 안내 4장(PC 1280×720, 모바일 720×1280)을 갱신했다. 개인 계정·기록·공개 글은 생성하지 않았다.
- KO/EN × 라이트/다크 × 320·360·390·768·900·1024·1440px, 총 28개 조건에서 헤더 겹침·가로 넘침·글자 설정·홈 이동·언어/테마 전환·키보드 포커스를 확인했다. 이름은 30px/700/-0.75px/36px, 부제는 9px/600/0.9px 대문자 설정이다.
- 검토 페이지의 320·390·1440px 이미지 20개와 다운로드 16개, 가이드 6개 페이지, 언어별 PWA 화면 파일과 PNG 20개 출력의 크기·알파·해시를 확인했다. 브라우저 오류는 0건이다.
- 서비스워커 캐시를 `ottline-cache-v6`으로 갱신했다. 격리 브라우저에서 이전 로고 캐시 제거, 현재 SVG 원본 일치, 오프라인 앱 아이콘 응답 200을 확인했다. 개인 기록을 보관하는 IndexedDB와 인증 데이터는 변경하지 않는다.
- 최종 Next.js 빌드·타입 검사, 변경 영역 Biome, SEO/복구/서비스워커 기존 검사 16개와 `git diff --check`를 통과했다. 검색창에 남아 있던 기존 lint 경고 3개는 이번 CI·검색 수정과 무관하다.

검증 결과·캡처는 `/tmp/ottline-ci-qa`, 폰트 비교는 `/tmp/ottline-ci-v2-original-font-actual-size.png`에 보관했다. 현재 기본 미리보기는 사용자가 원래 쓰던 WSL 3000 포트와 고정 ngrok `https://unmellow-dimple-untouchably.ngrok-free.dev`로 복원했다. CI 검토 페이지는 `/brand/v2/index.html`이다. 실행·동기화 검증의 후속 정정은 [웹 통합 문서](ottline-ux-v2-web.md)를 따른다.

## 브라우저 파비콘 투명 배경 (2026-11-07)

브라우저 탭에 크림색 정사각형이 보이던 파비콘을 투명 SVG·RGBA PNG·32비트 ICO로 바꾼다. 기존 열린 책·재생 심볼의 모양과 크기는 유지하고 SVG는 밝은 탭에는 navy, 어두운 탭에는 기존 cream 역상색을 사용한다. PNG·ICO fallback은 투명 navy 심볼로 만든다. PWA·Apple 앱 아이콘과 헤더·워드마크·스토어 자산은 이번 범위에서 변경하지 않는다.

생성 원본에서도 사각 배경과 불투명 평탄화를 제거해 다시 생성해도 투명도를 유지한다. 파비콘만 갱신하는 생성 경로로 관련 없는 자산의 변경을 막고, 메타데이터의 PNG·SVG URL에는 버전을 붙여 기존 브라우저 아이콘 캐시와 구별한다. 네 가지 크기의 알파·ICO 각 프레임·동일 복사본과 비파비콘 자산 해시를 확인하고, 밝은/어두운 브라우저 렌더링과 실제 head 링크·HTTP 응답을 검증한다.

검증 완료: 16/24/32/48px PNG 모두 RGBA이며 네 모서리 알파가 0이다. ICO의 네 프레임은 각각 32비트 PNG와 같고, brand/app/public의 세 복사본도 일치한다. 비파비콘 파일 37개와 해당 매니페스트·안전 영역 정보가 그대로 유지됐다. 파비콘만 재생성한 결과와 격리 폴더의 전체 생성 결과가 현재 자산과 일치해 재생성도 확인했다.

Next.js 빌드·타입 검사, 생성 스크립트와 layout의 Biome·diff 검사를 통과했다. 브라우저에서 실제 head의 새 PNG/SVG 버전 주소, 제공한 PNG 알파와 ICO 원본 일치, SVG의 light navy `rgb(30,77,140)` / dark cream `rgb(248,246,242)`를 확인했다. 16/24/32/48px의 밝은/어두운 배경 렌더링에서도 사각 바탕 없이 심볼만 표시됐다. 실제 브라우저 탭 막대를 캡처한 검증으로 표현하지 않는다.

기존 3000에 적용한 뒤 같은 검사를 다시 통과했다. WSL `172.24.75.199:3000`과 고정 ngrok에서도 홈·버전이 붙은 SVG·PNG가 200이고 제공 파일의 해시가 원본과 일치했다. 검증 전용 3218 서버는 종료했다. 브라우저 검사에서는 API 응답을 격리해 계정·기록을 만들지 않았다. 투명 파비콘 기준은 프로젝트 선호에 남겼으며 기존 기록·인증·서비스워커 캐시 버전은 변경하지 않았다.

이전 파일·빌드는 제외된 `.recovery/ottline-v2/snapshots`와 `favicon-asset-before`, 생성 검증은 `favicon-asset-validation`과 `favicon-generator-repro`, 최종 HTTP·브라우저·명암별 렌더링 근거는 `favicon-transparent-qa`에 보관한다.
