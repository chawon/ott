## 사용자 문제와 완료 조건

### 현재 동작과 문제
- 현재 ottline은 [timeline-export.md](../timeline-export.md) 기반의 CSV 내보내기와 Windows 앱의 Netflix CSV 가져오기만 제공한다.
- [#159 경쟁·인접 제품 리서치](../research/competitor-landscape-2026-11.md)에서 확인했듯 TV Time 서비스 종료(`2026-07-15`), 국내 영상 평가 서비스 재편 보도(`2026-08`) 등으로 기존 기록의 보관·이전을 고민하는 사용자가 존재하지만, ottline으로 옮겨올 때 기존 기록을 하나씩 다시 입력해야 하는 장벽이 있다.
- 또한 ottline 자체 CSV로 내보낸 파일을 다시 불러오는 경로가 없어, 사용자가 내보내기 파일을 실질적인 개인 아카이브로 활용하기 어렵다.

### 적용 가설과 기대 경험
- **가설**: 공식 내보내기 파일(CSV)을 업로드해 **미리보기 확인 후 안전하게 개인 타임라인으로 가져오는 흐름**을 제공하면, 기존 타 서비스 기록 보유자의 초기 전환 장벽이 낮아지고 이후 반복 기록 정착에 기여할 것이다. *(경쟁사의 기능 보유만으로 효과를 단정하지 않고 출시 후 지표로 검증한다.)*
- **기대 사용자 흐름 (4단계)**:
  1. **파일 선택 (로컬 파일 업로드)**: 지원 포맷 안내를 보고 사용자가 직접 내려받은 CSV 파일을 선택한다.
  2. **매칭 결과 미리보기 (저장 전 검토 필수)**: 전체 행 수, `새로 추가될 기록` / `이미 있는 기록(기본: 건너뛰기)` / `후보 확인 필요` / `매칭 실패`를 명확히 구분해 보여준다.
  3. **사용자 선택·확정**: 사용자는 개별 항목을 제외하거나 후보를 고른 뒤, 가져올 건수를 확인하고 명시적으로 `가져오기 실행`을 누른다.
  4. **안전한 반영 및 결과 요약**: 개인 타임라인에만 저장되며(자동 공개 금지), 성공·건너뜀·실패 건수와 실패 사유를 요약 안내한다.

### 완료 조건 (기획 인수 기준)
1. 사용자가 미리보기에서 확정하기 전에는 실제 기록이 1건도 저장되지 않는다.
2. 기존 ottline 기록이 있는 작품·책 판본에 대해 기본값으로 덮어쓰기가 발생하지 않으며, 기존 메모·TPO·수정 이력이 보존된다.
3. 가져온 기록은 어떤 경우에도 `함께` 공개 대화나 공개 댓글로 자동 게시되지 않는다.
4. 동일 파일을 다시 업로드하거나 진행 중 중단 후 재시도해도 중복 기록이 생성되지 않는다.
5. 대량 가져오기 도중/직후에도 사용자의 일반 기록 저장·수정·동기화 흐름이 멈추지 않는다.
6. 한국어·영어(KO/EN)에서 지원 포맷 안내, 미리보기 상태, 건너뜀/실패 안내가 자연스럽게 제공된다.

## 공통 목표와 플랫폼 차이

- **관련 기능 기준표 항목**([feature-matrix.md](../feature-matrix.md)): `1. 검색과 작품 선택`(작품·판본 ID 보존), `2. 기록 저장·수정·이력`, `4. 동기화·오프라인`, `8. 삭제·초기화`(개별 삭제 없음 원칙과의 정합).
- **지원 포맷 단계 범위 (기획 제안)**:
  - **1차 범위 (공식 CSV 구조가 명확한 포맷 우선)**:
    1. **ottline 자체 CSV**: [timeline-export.md](../timeline-export.md) 내보내기 파일 재가져오기(개인 보관·복구 신뢰 완성).
    2. **Letterboxd CSV**: 글로벌 영화 기록 (`diary.csv` / `watched.csv` / `ratings.csv` 중 기준 파일은 기술·포맷 검증에서 확정).
    3. **Goodreads / StoryGraph CSV**: 글로벌 도서 기록 (ISBN 기반 판본 매칭 가능).
    4. **Netflix 시청 기록 CSV**: 기존 Windows에 있는 가져오기 경험을 공통 기준으로 정렬할지 검토.
  - **2차 범위 (실제 공식 내보내기 가능 여부·파일 구조 확인 후 추가)**:
    - 국내 주요 서비스(**왓챠피디아 · 북모리 · 북적북적 · 키노라이츠**): 실제 서비스의 공식 사용자 파일 내보내기 제공 여부와 최신 파일 컬럼 구조를 확인한 뒤 검증된 포맷만 추가한다(미확인 포맷을 1차에 확정하지 않음).
  - **영구 제외 범위**:
    - 타 서비스 계정 ID/비밀번호 입력 대행, 비공식 크롤링/스크래핑 방식은 프라이버시·약관 충돌로 지원하지 않는다.
- **플랫폼별 지원 범위**:
  - **1단계 (공통 진입점 — Web/PWA 우선)**: 파일 선택과 다건 미리보기 검토는 큰 화면 브라우저가 가장 자연스럽고, Web/PWA에서 가져온 기록은 기존 계정 동기화를 통해 Android·iOS/iPadOS·macOS·Windows에 그대로 반영된다.
  - **2단계 (네이티브 앱 검토)**: Web/PWA 운영 결과와 모바일 파일 가져오기 수요가 확인되면 iOS/iPadOS·Android·macOS·Windows 확장을 별도 판단한다. (기존 Windows의 Netflix CSV 가져오기는 공통 정책이 확정될 때 정합화 검토.)
  - **명시적 미지원**: 브라우저 확장 · 토스 인앱 · ChatGPT 앱 (보조 채널 역할 범위 밖).

## 제품 정책과 필수 안전장치 (기획 요구사항)

> 아래는 제품이 보장해야 할 사용자 정책이며, 파싱 위치(클라이언트/서버)·매칭 API·배치 크기·outbox/동기화 제어는 API·플랫폼 담당의 기술 설계 범위다.

### 1. 개별 삭제 없음 정책 하에서의 사전 안전장치
- ottline은 사용자용 개별 기록 삭제를 제공하지 않는다([AGENTS.md](../../AGENTS.md)). 따라서 잘못된 대량 가져오기가 저장되면 사용자가 수십~수백 건을 일일이 되돌릴 수 없다.
- **필수 원칙**:
  - **저장 전 미리보기(Dry-Run) 확정**을 건너뛰는 "원클릭 즉시 가져오기"는 제공하지 않는다.
  - 파일당/회당 안전한 상한(건수 제한 또는 분할 안내)과 진행 중 중단 시 이미 반영된 건수/남은 건수의 명확한 표시를 둔다.

### 2. 작품·책 판본 매칭 및 미매칭 정책
- 기존 작품·시즌·책 판본(ISBN) ID 체계를 유지한다.
- 매칭 결과는 세 그룹으로 분리해 사용자에게 투명하게 안내한다:
  - **정확 매칭**: ISBN·공식 ID 또는 제목+연도/저자 일치로 확인된 항목.
  - **확인 필요(후보 복수)**: 동명 영화·시리즈 또는 복수 도서 판본이 존재해 사용자가 선택해야 하는 항목(자동 임의 확정 금지).
  - **미매칭**: 카탈로그에서 찾지 못한 항목 — 기본값은 **건너뛰기**로 두고 목록을 보여줘 사용자가 필요 시 수동 검색으로 추가할 수 있게 한다.

### 3. 중복 처리 및 수정 이력 보존 정책
- **기본 정책 (보수적 보호)**: 이미 ottline 타임라인에 같은 작품·책 판본 기록이 존재하면 **기본값은 `기존 기록 유지(건너뛰기)`**로 둔다. 기존 사용자의 메모·TPO·상태·수정 이력을 덮어쓰지 않는다.
- 동일 파일 내 같은 작품의 여러 날짜(재감상/재독)가 있는 경우, ottline의 수정 이력 정책과 충돌하지 않는 처리 방식(최신 날짜 기록 + 이전 날짜 이력 반영 여부 vs 최신 1건만 반영)은 기술·정책 검토에서 확정한다.

### 4. 공개 범위 · 계측 · 추천 자격 정책
- **공개 범위**: 가져온 기록은 100% 개인 타임라인에만 저장하며, 공개 `함께` 게시·댓글·반응을 자동 생성하지 않는다.
- **계측 분리 ([`#169`](https://github.com/chawon/ott/issues/169) 연계)**: 과거 기록 수십~수백 건을 한 번에 가져오는 행위가 일상 기록(`log_create`)·첫 기록(`first_log_create`) 지표를 왜곡하지 않도록, 가져오기 전용 이벤트(시도·미리보기·완료·가져온 건수 구간)로 분리 집계하는 방향을 `#169`와 맞춰 정의한다.
- **미래의 타임라인 추천 자격 (사용자 결정 필요)**: 가져온 완료 기록을 추천 자격(완료 기록 5개 이상)과 취향 입력에 포함할지 여부는 제품 정책 판단이 필요하다. *(기획 추천안: 사용자가 미리보기에서 직접 확인해 가져온 완료 기록은 실제 감상·독서 이력이므로 추천 자격과 취향에 반영하되, 일일 추천 횟수 정책은 기존대로 유지.)*

## API·플랫폼 담당 기술 검토 요청 항목

구현 착수 전 아래 기술·운영 제약을 API·Web 담당과 확인한다:
1. 대량 작품/도서 매칭 시 외부 검색 API(TMDB·Kakao·Google Books) 호출 한도·응답 지연 및 캐시 활용 범위
2. 대량 저장 시 로컬 우선 outbox·동기화(`POST /api/sync/push`) 부하와 중단/재시도 시 중복 방지 보장 방식
3. 재감상/재독 다중 날짜 행을 ottline 기록·수정 이력 모델에 매핑할 때의 호환성과 기존 앱 영향
4. 가져오기 전용 계측 정의와 `#169` 공통 계측 정합성

## 사용자(제품 오너) 결정이 필요한 항목

1. **1차 지원 포맷 범위**: `ottline CSV + Letterboxd CSV + Goodreads/StoryGraph CSV (+ Netflix CSV 정렬 검토)`로 1차를 시작하고, 국내 서비스(왓챠피디아·북모리 등)는 공식 내보내기 구조 확인 후 2차로 붙이는 단계 적용에 동의하시는지?
2. **가져온 완료 기록의 추천 자격 포함 여부**: 가져온 완료 기록을 `미래의 타임라인` 5건 자격과 취향 분석에 포함할지 여부 (기획 추천: 포함).
