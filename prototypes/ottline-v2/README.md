# OTTLINE 2.0 interactive design preview

OTTLINE의 가입 없는 기록 경험과 코드 연결을 유지하는 **A 아카이브 확정 시안**입니다. 2026-11-02 사용자가 A를 선택했고, PC의 여유 있는 배치와 모바일 전용 기록 흐름을 이 방향으로 이어갑니다. **운영 적용 전 직접 검토하는 프로토타입**으로 샘플 체험과 개발 API 기록 조회를 지원합니다. 기록 쓰기·서버 동기화·계정 합치기는 샘플 체험에 한정합니다.

## 실행

저장소 루트에서 별도 의존성 설치 없이 실행합니다.

```sh
node prototypes/ottline-v2/serve.mjs
```

<http://localhost:4173>에서 열립니다. 서버는 `127.0.0.1`에만 바인딩합니다. 다른 포트가 필요하면 `PORT=4174`를 지정하세요. 종료는 실행한 터미널에서 Ctrl+C입니다.

WSL에서 실행하고 Windows 브라우저에서 WSL IP로 접속하려면 다음과 같이 실행합니다. 출력된 `Network` 주소를 여세요. WSL 재시작 후에는 IP가 달라질 수 있습니다.

```sh
node prototypes/ottline-v2/serve.mjs --host 0.0.0.0
```

로컬 IP의 HTTP 환경에서도 기록 생성과 코드 복사 대체 동작을 지원합니다. 브라우저가 복사를 허용하지 않으면 표시된 코드를 직접 선택해 복사할 수 있습니다.

- A 아카이브: `http://localhost:4173/?variant=archive`
- 첫 방문: `http://localhost:4173/?scenario=new`
- 새 기기: `http://localhost:4173/?scenario=new-device`
- 영어·다크: `http://localhost:4173/?lang=en&theme=dark`

상단에는 PC·모바일 모두 **A 아카이브**를 표시합니다. 예전 `?variant=journal` 주소도 A로 연결됩니다. 비교 시안은 Git 커밋 `9132db4`에 남아 있습니다. 언어·테마·데이터·사용자 상황·연결 상태는 미리보기 도구에서 바꾸며, 모바일에서는 **미리보기 설정**을 펼쳐 사용합니다. 샘플 모드의 상황 선택은 해당 화면의 샘플을 불러오고, 초기화는 샘플을 원래 상태로 되돌립니다. **온라인/오프라인 체험 전환은 기록을 유지**하며 실제 기기의 인터넷 연결을 바꾸지 않습니다. 새로고침하면 샘플 체험 상태가 초기화됩니다.

## 로컬 개발 API 연결

기존 로컬 API가 `http://127.0.0.1:8080`에서 실행 중일 때 다음과 같이 시안 서버를 실행합니다.

```sh
PREVIEW_API_URL=http://127.0.0.1:8080 node prototypes/ottline-v2/serve.mjs --host 0.0.0.0
```

`http://localhost:4173/?data=development`를 열거나 상단 데이터 선택을 **개발 데이터**로 바꾸고 **개발 계정의 기록 연결 코드**를 입력합니다. WSL IP와 ngrok 주소에서도 같은 경로를 사용합니다. API 주소는 서버 환경변수로만 정하며 브라우저에 직접 API 포트를 열지 않습니다.

- 코드 입력은 기존 `POST /api/auth/pair`로 개발 계정에 미리보기 기기를 연결합니다. 계정 합치기에 쓰이는 `oldUserId`는 보내지 않습니다. 샘플 계정·기록은 전송하지 않습니다.
- 이후에는 `GET /api/logs/page`와 `GET /api/auth/profile`만 사용합니다. 커서가 끝날 때까지 전체 기록을 가져오고 날짜·TPO·메모·별점·시즌 표지를 표시합니다. 홈·내 기록·상세·리포트는 가져온 기록을 사용하며 함께 화면에는 가상 게시물을 섞지 않습니다. API에 없는 KDC 분류는 추정하지 않습니다.
- 개발 모드는 조회용입니다. 기록 추가·수정·공개·합치기는 노출하지 않으며 프록시에서도 해당 쓰기 요청을 허용하지 않습니다. 연결 실패나 빈 계정에 샘플 기록을 대신 표시하지 않습니다.
- 인증 ID는 시안 서버 메모리에 보관하고 브라우저에는 무작위 HttpOnly 세션 쿠키만 둡니다. 유효기간은 8시간이며 서버 재시작 후에는 코드를 다시 입력합니다. 연결 코드나 ID를 URL·로그·localStorage에 넣지 않습니다.
- 미리보기 연결 해제는 쿠키와 시안 세션을 지웁니다. 개발 계정에 등록한 기기는 기존 서비스의 기기 관리에서 해제할 수 있습니다. 브라우저마다 자신의 코드로 연결합니다.
- 실제 포스터·책 표지는 API가 제공한 HTTPS 이미지 주소에서 불러옵니다. 표지가 없으면 제목을 표시합니다.

이번 WSL에서는 기존 `local` 설정의 PostgreSQL(`localhost:5433/watchlog`)을 사용합니다. 스키마가 이미 준비된 이 개발 DB에 한해 다음 명령으로 API를 실행했으며, 자동 마이그레이션과 예약 작업을 껐습니다. 새 DB를 만드는 명령은 아닙니다.

```sh
cd apps/api
GRADLE_USER_HOME=/home/ergate23/workspace/ott/.gradle ./gradlew bootRun --no-daemon --max-workers=2 --args='--spring.profiles.active=local --server.address=127.0.0.1 --spring.flyway.enabled=false --report.schedule=- --analytics.retention.schedule=- --curator.automation.enabled=false --notify.telegram.enabled=false --spring.jpa.show-sql=false --logging.level.org.hibernate.SQL=WARN'
```

## 선택한 방향

| 방향 | PC | 모바일 홈의 우선순위 |
| --- | --- | --- |
| A 나의 시간 아카이브 | 월 탐색과 큰 표지·TPO·감상으로 펼친 기록 한 장, 옆에 이어가는 작품 | 기록 진입과 가로 월 선택, 실제 기억 한 장, 그달의 기록을 세로로 탐색 |

PC의 여유 있는 배치는 유지합니다. 760px 이하에서는 모바일 전용 홈을 사용하고, 기록 입력은 아래에서 열리는 시트로 표시합니다. 첫 방문에는 첫 기록과 기존 기록 연결을 제공하며, 미전송 기록·오프라인·불러오기 오류 상태를 숨기지 않습니다. 월 선택과 작품 선택은 키보드와 터치로 사용할 수 있습니다.

공통 구조는 홈 / 내 기록 / 함께 / 내 공간과 상시 기록 버튼입니다. 네이비 워드마크와 오렌지 부제, 절제된 최종 행동 색상, 정지된 카드 호버를 유지했습니다. 새 분위기는 시안 안에 한정하며 저장소의 `DESIGN.md`를 교체하지 않았습니다.

### 2026-11-03 구조 개편

“괜찮지만 대규모 개편의 느낌은 약하다”는 피드백에 따라 홈과 기록 탐색을 다시 구성했습니다. 앞선 A안(`d73a89b`)은 PC 상단의 소개 문장·연결 안내 아래에 이어가는 작품, 최근 표지, 리포트를 차례로 배치해 같은 작품이 반복됐습니다. 새 A안은 실제 기록과 그날의 맥락부터 보여줍니다.

- **월로 펼치는 홈:** 기록이 있는 달을 선택하면 대표 기록과 그달의 기록이 바뀝니다. 최신 기록이 있는 달에서 시작하며, 현재 달에 기록이 없다고 홈을 비우지 않습니다.
- **기억을 여는 TPO:** 장소·상황을 누르면 해당 맥락의 내 기록으로 이동합니다. 선택한 조건을 화면에 표시하고 해제할 수 있으며, 제목·메모 검색과 유형·상태 조건을 함께 사용할 수 있습니다.
- **모바일의 첫 화면:** 짧은 기록 진입과 대표 기록의 제목·TPO를 우선합니다. 이어가는 작품 전체가 첫 화면에 들어가야 한다는 이전 검증 기준은 이 우선순위에 맞게 바꿉니다.
- **작은 연결 안내:** 개발 데이터가 정상적으로 열린 상태는 읽기 전용 표시와 내 공간 진입으로 간결하게 안내합니다. 연결·불러오기·오류 상태와 내 공간에는 필요한 조작을 계속 제공합니다.

월·장소·상황·수량은 실제 기록에서만 만듭니다. 날짜가 없는 기록이나 찜한 작품에 감상 시점을 만들지 않으며, 메모가 없으면 감상 문장을 대신 쓰지 않습니다. 이번 변경은 프로토타입의 홈·탐색 구조에 해당하며, 운영 웹이나 네이티브 앱 전체 개편의 완료를 의미하지 않습니다.

## TPO와 기록의 읽는 순서

TPO(언제, 어디서, 누구와·어떤 상황)는 입력과 회상 화면에 함께 반영합니다. 샘플은 집·가족, 카페·휴식, 극장·친구처럼 서로 다른 맥락과 정보를 남기지 않은 경우를 포함합니다.

| 화면 | 배치 |
| --- | --- |
| A 기록 카드·타임라인 | 작품과 상태 → 날짜·시간, 장소·상황 → 감상. 날짜가 별도 열에 있으면 카드 본문에서는 중복하지 않습니다. |
| 상세 | ‘언제 / 어디서 / 누구와·어떤 상황’으로 구분한 영역. 기록하지 않은 정보는 상세에서만 명확히 표시합니다. |
| 입력·수정 | 날짜·시간 전체 행과 장소·상황 선택. 모바일에서 내용은 스크롤하고 최종 상태 저장 버튼은 아래에 유지합니다. |

좁은 최근 표지 레일은 제목·날짜를 유지하고 전체 맥락은 기록 목록과 상세에서 확인합니다. 선택값은 배지로 나열하지 않고 조용한 텍스트로 묶어 줄바꿈합니다. 새 감상의 날짜·시간은 현재 기기 시간을 기본으로 하며 수정하거나 비울 수 있습니다. 장소·상황은 기본값을 추정하지 않습니다. 새 ‘보고/읽고 싶어요’ 기록에는 감상 맥락을 만들지 않고, 기존 기록을 이 상태로 바꿀 때는 앞서 남긴 맥락을 보존합니다.

## 한국어·영어 문구 기준

- 상태 질문은 아직 만나지 않은 작품도 포함하고, 맥락·감상 버튼은 처음 남길 때와 고칠 때 모두 자연스럽게 씁니다.
- 메모 없는 기록의 목록에는 대체 감상이나 결핍 문구를 반복하지 않습니다. 상세에서만 한 줄을 남기도록 가볍게 권합니다. 메모 없이 공개할 때도 작성하지 않은 문장을 인용하지 않습니다.
- 기록 완료의 안심 문구와 리포트의 무압박 문구를 유지합니다. 기기 저장과 서버 동기화 상태는 구별합니다.
- 한국어 소제목은 한글로 통일하고, 영상·책 공통 필터는 두 매체를 모두 포함합니다.
- 합치기는 더 최근 기록이 남는다는 기준, 예전 내용 일부가 사라질 가능성, 이전 코드·기기 재연결, 다시 나눌 수 없다는 설명을 함께 유지합니다.
- 온라인 전환은 미리보기 도구에만 두고 체험임을 표시합니다. 사용자 화면에 인터넷을 복구하는 것처럼 보이는 버튼을 두지 않습니다.

## 직접 눌러볼 순서

1. **첫 방문**을 선택하고 영화·시리즈·책을 검색합니다. 선택한 작품 아래에서 날짜·시간, 장소·상황을 남기고 상태를 누르면 기록됩니다. TPO를 채우지 않아도 저장할 수 있고, 저장 확인 뒤 맥락·메모·별점을 수정할 수 있습니다.
2. 내 기록에서 TPO와 감상의 배치, 제목·메모 검색, 유형·상태 필터, 상세 수정, 리포트 카드 다운로드를 확인합니다. 한국어에서 내 서가를 열면 KDC 0~9 순서로 표시됩니다.
3. 내 공간에서 기록 연결 코드 복사 또는 개인 보관 카드 PNG를 저장합니다. 같은 탭의 **새 기기** 상황으로 이동해 표시됐던 코드를 입력하고 서버에 동기화된 샘플 기록을 불러옵니다.
4. 별도 계정의 체험 코드는 **M7K2 P9WX**입니다. 기록이 있는 상황에서 입력하면 합치기 확인이 먼저 표시됩니다. 중복 작품은 최근 수정 내용이 남고, 이전 코드·기기는 재연결이 필요하다는 영향을 안내합니다.
5. **오프라인**에서 기록을 추가하고, 상단 연결 상태를 온라인으로 바꾼 뒤 동기화를 재시도합니다. **동기화 오류**에서는 전송 완료 전 합치기를 막습니다.
6. **불러오기 오류**에서 연결하고, 오류 화면을 닫았다가 내 공간에서 불러오기를 이어갑니다. 기록을 실제로 표시하기 전에는 완료로 안내하지 않습니다.
7. 상세에서 공개 확인을 거쳐 함께 화면에 나눕니다. 오프라인에서는 인터넷 연결 뒤 다시 시도하도록 안내합니다.
8. 언어·테마·모바일 너비를 바꿔 동일한 과제를 반복합니다.

## 데이터와 구현 경계

- 샘플 모드의 작품·작가·감상·반응 수·코드는 모두 가상입니다. 샘플 사진은 가상 작품의 표지를 표현하는 이미지이며 실제 배급 포스터나 출판 표지가 아닙니다. 출처와 라이선스는 `assets/attribution.md`에 있습니다.
- 샘플 데이터와 계정은 현재 페이지의 메모리에만 있습니다. IndexedDB·운영 API·분석 이벤트를 사용하지 않습니다. 개발 모드의 실제 데이터와 섞지 않습니다.
- CSP의 `connect-src 'self'`는 같은 시안 서버의 제한된 API 프록시 요청만 허용합니다. 폰트·샘플 사진은 로컬 파일이며 개발 데이터의 HTTPS 표지도 허용합니다. 서버는 프로토타입의 웹 자산만 제공하고 상위 저장소 파일은 제공하지 않습니다.
- 사용자 메모는 HTML로 실행하지 않으며, CSV 내보내기는 수식 시작 문자를 이스케이프합니다. PNG 다운로드에는 시안용 샘플임을 표시합니다.
- CSV에는 TPO를 포함합니다. 함께 공개에는 기존 작품·감상·날짜만 전달하고 장소·상황은 포함하지 않습니다. 화면의 날짜·시간은 기기 시간대를 따르며 CSV는 ISO 시각을 사용합니다.
- 이메일·소셜 로그인, 실제 개인정보 수집, 새 복구 서비스, QR 연결, 운영 DB/API 변경, 앱 스토어 배포는 포함하지 않습니다.

## 실제 서비스 반영 순서

1. 확정한 A 시안의 패턴과 문구를 웹의 공통 메뉴·홈·기록 완료·내 공간부터 적용합니다.
2. 기존 `/`, `/timeline`, `/public`, `/account`, 리포트·서가 URL을 호환하고 확장·공유·Android 알림 진입의 작품/플랫폼 정보를 유지합니다.
3. 기존 8자리 코드와 인증·동기화 API를 기본으로 유지합니다. 웹 연결 직후 전체 기록 pull, 동기화 완료 판정, 미전송 기록 보호는 실제 클라이언트 테스트로 검증해야 합니다. 현재 시안의 메모리 상태 처리를 운영 저장 로직으로 복사하지 않습니다.
4. 웹·PWA·Android TWA 및 토스·확장 진입을 검증한 뒤 iOS에 같은 정보 구조와 용어를 네이티브 방식으로 반영합니다. ChatGPT의 읽기 전용 역할을 유지합니다.
5. 기존 분석 체계에서 첫 기록·후속 기록·연결·회상 이용을 비교하되 코드나 감상 원문을 수집하지 않습니다. 이번 시안으로 이탈 원인이나 지표 개선이 입증된 것은 아닙니다.
