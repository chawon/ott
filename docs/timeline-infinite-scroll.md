# 타임라인 무한 스크롤

## 범위와 설계

- 웹/PWA/Android TWA의 개인 타임라인은 서버에서 처음 50개, 이후 스크롤마다 다음 50개를 조회한다.
- 기존 배열 응답 `GET /api/logs`는 다른 호출부의 하위 호환을 위해 유지한다. 타임라인은 새 `GET /api/logs/page`를 사용한다.
- 페이지 응답은 `items`와 불투명 `nextCursor`를 제공한다. 커서는 선택한 정렬 키(`sort=history`면 `updatedAt`, 기본이면 `watchedAt`)와 UUID를 묶은 키셋 커서다. 같은 시각의 기록도 UUID 역순으로 안정적으로 이어진다.
- `contentType=book|video`를 서버 필터에 포함해 책 또는 영상 필터에서도 페이지마다 최대 50개의 일치 기록을 받는다.
- 받은 페이지는 IndexedDB에 upsert한 뒤 렌더한다. 이미 동기화된 로컬 기록은 첫 화면과 오프라인 추가 조회에 사용하지만, 온라인 다음 페이지의 기준은 서버 커서다.
- 필터 변경 시 서버 커서와 표시 범위를 초기화한다. 이전 필터의 비동기 결과는 폐기하며, 동기화 중에는 펼친 범위를 유지한다.
- 하단 감지 영역과 키보드/미지원 브라우저용 추가 조회 버튼, 로딩/재시도/끝 안내를 한국어·영어로 제공한다.
- DB 스키마와 iOS 네이티브 앱은 변경하지 않았다. 새 API를 먼저 배포한 뒤 웹을 배포했다.

## 검증 시나리오

- 로컬 기록이 비어 있는 실제 브라우저에서 가짜 서버가 50/50/25개를 응답하도록 하고 50 → 100 → 125개 표시, 요청 커서, 중복 없음을 확인한다.
- 0/50/51개 경계와 첫 묶음 밖의 과거 기록 검색 확인.
- 서버 페이지가 IndexedDB에 저장된 뒤 오프라인 추가 조회와 `sync:updated` 뒤 펼친 범위 유지 확인.
- 모바일 자동 조회와 모바일/데스크톱 수동 추가 조회 확인.
- 한국어·영어 메시지 구조와 CSV 전체 내보내기의 무제한 로컬 조회 유지 확인.
- API 커서 단위 테스트, PostgreSQL 저장소 통합 테스트, 웹 타입 검사, 프로덕션 빌드를 수행한다.

## 검증 결과

- Playwright: 빈 IndexedDB에서 서버 페이지 50/50/25개를 받아 50 → 100 → 125개 표시, 요청 커서 순서와 중복 없음 확인.
- Playwright: 서버 페이지 캐시 후 오프라인 추가 조회, 첫 페이지 밖 검색, 50/51개 경계, 모바일 자동 조회와 수동 추가 조회 확인.
- API: 커서 왕복·정렬 불일치 거부, `limit + 1` 조회와 마지막 노출 항목 기반 다음 커서 생성을 포함한 전체 Gradle 테스트 통과.
- PostgreSQL 저장소 통합 테스트는 로컬 Docker 부재로 건너뛰었고, PR·main API CI의 Docker 환경에서 실제 키셋 SQL과 `book|video` 필터까지 통과했다.
- 웹: TypeScript 검사, 변경 파일 Biome 검사, Next.js 프로덕션 빌드 통과.
