# 미래의 타임라인 — OpenAI 전환과 재노출 검토

이 문서는 최초 OpenAI 전환 당시의 검토 기록이다. 아래 후속 과제는 이후 사용자 승인으로 구현했으며, **현재 정책과 계약은 [계정별 추천 정책](future-timeline-account-policy.md)**을 따른다.

## 범위와 현재 결과

`2026-11-08` 사용자 요청으로 기존 ‘추천 기능은 범위 밖’ 원칙의 예외를 적용했다. 기존 `feature/ottline-ux-v2-web`에서 API·웹을 수정한다. Google Books 연결은 보류하며 네이티브 앱과 운영 배포는 포함하지 않는다.

개발 키는 루트 `.env.local`의 `OPENAI_API_KEY`에서 읽어 API 전용 비공개 런타임 파일에 전달했다. OpenAI **`gpt-6-luna` / `reasoning.effort=low`**를 사용한다. 모델은 `OPENAI_MODEL`로 바꿀 수 있다. 키 값은 Git·문서·웹 번들에 넣지 않았다.

OpenAI Responses API와 엄격한 JSON Schema로 추천을 받는다. 거절·불완전 응답·잘못된 JSON·시간 초과는 성공으로 저장하지 않는다. 개발 키의 모델 조회와 실제 추천 호출을 모두 확인했다. OpenAI가 설정되면 Anthropic/Gemini는 함께 호출하지 않는다.

## 검증

- 최초 서버 회귀 5개는 변경 전에 모두 실패했다. 캐시 제외·오래된 기록 제외·새 생성의 오래된 기록 제외·정규화·언어 경계를 검증한다.
- OpenAI 요청 URL·Bearer 인증·Structured Outputs·추론 옵션·거절/불완전/잘못된 응답·HTTP 오류·시간 초과·키 누락을 검증했다. 외부 오류 본문이나 키 값이 오류 메시지에 들어가지 않는다.
- 동명 작품의 잘못된 포스터와 1년 차이의 개봉 연도 두 회귀도 변경 전 실패를 확인했다.
- API 서비스·제공자·프롬프트 테스트 21개 통과. Spring 실제 시작과 PostgreSQL에서 신규 조회 쿼리도 확인했다. 전체 Testcontainers 테스트를 실행했다는 의미는 아니다.
- 로컬 설정 helper 테스트 7개와 격리 브라우저 최종 10개 시나리오를 통과했다. 제외→새 추천→재진입, 새 추천 503 후 재시도, 첫 조회 503 후 재시도, 모두 숨긴 빈 화면, 계정 전환 중 늦은 응답, 언어 변경, 예전 키 마이그레이션, 새 추천·요청 진행 중 되돌리기를 확인했다. 모든 API 요청을 가로채 실제 사용자 데이터에 쓰지 않았다.
- Next.js 16.3.8 빌드와 TypeScript·수정 파일 Biome 검사를 통과했다. 모바일 KO/EN의 제목 줄바꿈과 가로 넘침도 화면으로 확인했다.

실제 개발 API 검증은 별도로 만든 계정과 2026년 1월의 합성 DONE 기록 5개로 수행했다. WSL `172.24.75.199:3000`의 웹 프록시를 통해 실제 OpenAI·TMDB를 호출했다.

| 요청 | 결과 | 관측 시간 |
|---|---|---|
| 한국어 첫 추천 | 200, 추천 5개, `openai:gpt-6-luna:low` 캐시 | 13.460초 |
| 같은 캐시에서 첫 작품 제외 | 200, 4개, 제외 작품 없음 | 0.320초 |
| 제외를 유지한 새 추천 | 200, 5개, 제외 작품 없음 | 10.043초 |
| `en-US,en;q=0.9` 전환 | 200, 영문 이유가 있는 추천 5개 | 5.416초 |

시간은 이 개발 환경에서 한 차례 관측한 값이며 성능 보장은 아니다. 검증 뒤 해당 QA 계정과 그때 새로 만든 미참조 제목만 정리했다. 기존 사용자 기록은 사용하거나 지우지 않았다.

로컬 비공개 근거는 `.recovery/ottline-v2/future-ux-red/`, `future-ux-final-*/`, `future-ux-live-3000/`, `future-openai-real/result.json`에 있다. 여기에는 실제 사용자 기록 대신 합성 결과만 남겼다. 검증된 빌드를 기존 3000 포트에 적용했고 WSL 한·영 타임라인, API health, 고정 ngrok 모두 HTTP 200을 확인했다. 3000의 실제 번들에서도 되돌리기 회귀 테스트를 다시 통과했다.

## 최초 검토 당시의 후속 과제

| 우선순위 | 한계 | 다음 작업 기준 |
|---|---|---|
| P2 | ‘이미 본·읽은 작품’의 수동 제외는 계정별 **기기 로컬** 저장이다. 다른 기기로 동기화되지 않는다. 실제 개인 기록으로 남긴 작품의 제외는 서버 전체 기록에 적용된다. | 기기 사이에서도 같은 제외를 원하면 별도 계정별 제외 저장소와 sync 계약을 추가한다. 시청·독서 기록을 임의 생성하지 않는다. |
| P2 | 하루 한 번 새 추천은 브라우저의 로컬 날짜에 따른 UI 제한이다. 서버 비용 제한이 아니며 동시 생성 요청 합치기도 없다. | 운영 전 서버 생성 한도·시간 기준·동시 요청 정책을 별도로 정한다. 현재 검증을 서버 과금 제한이 해결됐다고 해석하지 않는다. |
| P2 | `/sync/push`는 추천 캐시를 무효화하지 않는다. 전체 기록 필터로 방금 기록한 작품은 바로 숨겨지지만 취향은 기존 24시간 캐시가 남을 수 있다. | 새 느낌·메모를 다음 조회에 즉시 반영할지 결정하고 sync 저장 후 캐시 무효화를 연결한다. 현재는 ‘다른 이야기 펼쳐보기’로 다시 생성할 수 있다. |
| P2 | 기존 `excluded=<제목>` 계약은 종류·판본을 특정하지 못한다. 동명의 영화/책을 함께 거를 수 있다. 책은 원제·ISBN을 검증하는 보완이 없어 번역명 차이를 완전히 해결하지 못한다. | 구조화한 제외 ID와 책 카탈로그 검증을 후속으로 추가한다. Google Books 연결은 이번 요청에 따라 보류했다. |
| P2 | 카탈로그 장애·모호한 검색 결과에는 포스터/ID 없는 텍스트 추천을 유지한다. 추천 카드에서 기록 또는 상세로 바로 이동하는 동선은 아직 없다. | 영상/책 판본을 확인해 선택 가능한 검색 결과로 연결하는 흐름을 다음 UX 범위로 검토한다. |
