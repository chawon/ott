# 마케팅 담당과 유입 개선 운영

2026-11-22 사용자 요청으로 마케팅 담당을 둔다. 목표는 **서비스 발견 → 첫 기록 → 반복 이용**이다. 채널별 유입과 전달할 가치를 관리하고, 첫 기록·재방문 개선은 제품 기획과 함께 판단한다.

## 담당 범위

| 업무 | 산출물 |
| --- | --- |
| 대상·가치 정리 | 어떤 사용자가 어떤 상황에서 ottline을 찾는지, 실제 제공하는 가치와 첫 행동 |
| 검색·스토어·공유 등 채널 검토 | 채널별 현재 근거, 지원 언어·플랫폼, 진입 경로와 측정 공백 |
| 출시·서비스 안내 | 실제 공개 버전과 기능 범위에 맞춘 KO/EN 소개·스토어/가이드 문구·자산 초안 |
| 유입·전환 실험 | 대상·메시지·노출 위치·기간·계측·성공/중단 기준·필요 비용과 담당 |
| 성과 검토 | 유입·첫 기록·반복 이용의 기준선과 결과, 한계 및 다음 제안 |

기능 제공 여부와 출시 상태는 [플랫폼 현황](platforms.md)·[기능 기준표](feature-matrix.md)·각 담당의 근거를 따른다. 공개 안내의 주장과 실제 설치판이 일치해야 한다. 공개 자산은 개인정보·연결 코드가 노출되지 않는 예시 자료를 사용한다.

## 기획·본부·개발과의 연결

| 담당 | 책임 |
| --- | --- |
| 마케팅 담당 | 대상·채널·메시지·출시 안내 초안·유입 실험과 결과 해석 |
| 제품 기획 담당 | 사용자 문제·제품 행동·공통 기능 기준·플랫폼 차이·개선 범위 |
| 플랫폼·API 담당 | 앱 화면·링크·계측의 구현, 호환성·테스트·PR·실제 배포 |
| 운영 담당 | 통계 조회, 집계 정의·기간·제외 조건과 접근 가능한 자료 확인 |
| 관리 본부 | 우선순위·담당·의존성·출시/실행 순서·완료 근거 조율 |

마케팅이 기능·화면·새 계측을 제안하면 기획에서 제품 기준을 대조하고 본부가 해당 개발 카드에 연결한다. 예를 들어 서비스 가이드 문구의 목적·대상은 마케팅이 제안하고, 실제 Web 반영은 Web 담당의 PR로 진행한다. 기존 [기획 운영 흐름](product-planning.md)에 마케팅 근거를 함께 연결한다.

## 성과를 읽는 기준

- 검색 노출·검색어·클릭은 검색 콘솔, 스토어 조회·설치는 해당 스토어 자료, 사이트 진입 뒤 행동은 자체 유입 집계를 출처로 삼는다. 클릭·설치·첫 실행·첫 기록을 각각 기록한다.
- 기간·채널·언어·플랫폼, 분자·분모와 계정/클라이언트/세션 단위를 명시한다. 세션 지표를 사용자 수로 바꾸어 부르거나 웹·네이티브·스토어 수치를 임의로 합산하지 않는다.
- 운영자·테스트·모의 유입을 구분한다. 실제 ChatGPT 답변의 언급/인용, 해당 출처의 실제 방문, 첫 기록은 서로 다른 관찰 결과다. 현재 미운영인 ChatGPT 앱의 출시를 의미하지 않는다.
- 여러 주의 반복 기록과 여러 기기의 실제 이용은 기획·운영 담당과 정의를 맞춘다. 연결 기기 수만으로 지속 이용이나 물리적 기기 수를 판단하지 않는다.
- 자료가 적으면 절대 건수·사용자 피드백·측정 한계를 함께 보고한다. 같은 정의의 기준선과 실행 후 결과를 비교하며 인과관계를 과장하지 않는다.

세부 계측은 [유입 기반 문서](seo-acquisition-foundation-2026-07-19.md)와 [공통 계약](product-contracts.md)을 따른다. 캠페인 링크에는 기존 허용 파라미터를 사용하고 연결 코드·계정/기기 식별자를 넣지 않는다. 검색 유입·성과를 위해 개인 화면의 색인 경계를 변경하는 제안은 별도의 제품·기술 검토에 연결한다.

## 실행과 검토

기준선 확인 → 대상·메시지와 실험안 작성 → 기획의 제품 정합성 확인 → 본부의 실행 범위 조율 → 담당별 실행 → 결과와 다음 개선안을 기록한다. 기존 주간 사용 통계를 성과 검토의 입력으로 사용한다.

실행안에는 대상·채널·문구/자산·진입 링크·실제 지원 버전·측정 방법·기간·필요 비용·담당·성공/중단 기준을 포함한다. 외부 게시·메일 발송·광고비 집행은 검토 가능한 초안을 준비한 뒤 해당 실행에 대한 명시적 지시가 있을 때 진행한다.

기획 카드의 완료는 검토 가능한 자료와 실행안을 만든 상태다. 실제 공개·배포와 실험 결과는 연결된 실행 카드에서 관리한다.
