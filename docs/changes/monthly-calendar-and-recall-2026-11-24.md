## 사용자 문제와 기존 화면과의 구분

### 현재 동작과 문제
- **기존 Web 홈 ([HomeTimelineView.tsx](../../apps/web/components/timeline-v2/HomeTimelineView.tsx))**:
  - 홈에는 이미 완료(`DONE`) 기록만 월 단위로 묶어 대표작과 요약을 보여주는 **월별 보기**와, 장소(`place`)·상황(`occasion`) 기준으로 `/timeline` 필터 링크를 제공하는 **‘다시 만나는 그날’** 진입이 존재한다.
- **기존 `/timeline` 목록 ([timeline/page.tsx](../../apps/web/app/%5Blocale%5D/timeline/page.tsx))**:
  - 현행 타임라인 목록은 마지막 **수정일(`updatedAt`)** 순으로 월 그룹을 나누며 50건씩 페이지 조회한다.
- **남아 있는 사용자 문제**:
  - 완료+진행 중 감상·독서 기록을 **감상·독서 날짜(`watchedAt`)별 일별 포스터/표지 달력**으로 한눈에 돌아보는 경험이 없다.
  - 홈의 ‘다시 만나는 그날’(장소·상황별 필터 목록 진입)과 달리, **과거 특정 시점의 완료 기록 1건을 직접 꺼내어 바로 해당 작품 상세·수정 이력으로 이어주는 개별 기억 회상 카드**가 없다.

### 기존 기능 vs 새 2순위 기능 구분

| 구분 | 기존 Web 홈 기능 (유지) | 새 2순위 기능 (`#176`, 1단계 Web/PWA) |
| --- | --- | --- |
| **월간 탐색** | 홈의 **완료 기록 월별 보기** (완료 기록만 월 단위로 묶은 요약·대표작) | **`/timeline` 상단 `목록 \| 달력` 전환** — 완료+진행 중 기록(위시리스트는 필터 선택)을 `watchedAt` 기준 **일별 7열 포스터/표지 달력**으로 표시 |
| **회상 진입** | 홈의 **‘다시 만나는 그날’** (장소·상황별 필터가 걸린 타임라인 목록으로 이동) | **타임라인 내 저부담 회상 카드** — 과거 특정 완료 기록 1건(작품·감상일·실제 있는 TPO/메모)을 보여주고 바로 **해당 작품 상세·수정 이력**으로 연결 |

### 검증할 가설
- **가설**: 기존 목록·홈 흐름을 해치지 않으면서 타임라인에 **일별 포스터/표지 월간 달력**과 과거 완료 기록 보유자 대상 **저부담 회상 카드**를 제공하면, "새로 기록할 때만 여는 앱"에서 "기억을 돌아보기 위해 다시 여는 앱"으로 사용 맥락이 확장되어 탐색 참여와 반복 기록에 긍정적 영향을 줄 것이다. *(경쟁사 기능 관찰만으로 효과를 단정하지 않고 출시 후 지표로 검증한다.)*

## 기대 사용자 흐름과 정책 (1단계 Web/PWA)

### 1) 월간 기록 달력 (`/timeline` 상단 `목록 | 달력` 보기 전환)
- **기본 상태와 필터 연동**:
  - 기존 `전체 / 영상 / 책` 필터와 연동한다.
  - **기본 달력 표시 상태**: `봤어요·읽었어요` + `보는 중·읽는 중`.
  - **위시리스트 선택 필터**: 사용자가 필터에서 `보고 싶어요·읽고 싶어요`를 선택하면 해당 기록도 함께 표시한다.
- **날짜 배치 기준**:
  - 목록의 마지막 수정일(`updatedAt`)과 구분해, 달력은 **`watchedAt`(감상·독서 날짜)**에 해당하는 **현재 기록 1건**을 배치한다(과거 수정 이력은 작품 상세에서 확인).
- **하루에 여러 기록(2건 이상)이 있는 날**:
  - 날짜 칸에는 대표 포스터/표지 1장을 보여주고 작은 건수 표기(예: `+1`, `+2`)로 추가 기록이 있음을 알린다.
  - 대표 이미지 우선순위: **포스터/표지가 있는 완료 기록 우선 → 최신 감상일 및 안정적 순서**.
  - 날짜를 선택하면 그날 남긴 전체 기록(제목·상태·실제 있는 **TPO(장소·상황)**·메모)에 접근하고 각 작품 상세·수정 이력으로 이동할 수 있다.
- **포스터·메모 부재 처리**:
  - 포스터/표지가 없거나 오프라인·요청 실패로 이미지를 불러올 수 없을 때는 빈칸 대신 따뜻한 중립 카드 위에 짧은 제목을 표시한다.
  - 메모가 없는 기록도 온전한 기록으로 취급하며, "메모가 없어요" 같은 결핍 문구를 노출하지 않는다(`.omd/preferences.md` 기준).
- **데스크톱·태블릿 vs 모바일 경험 분리 (`.omd/preferences.md` 기준)**:
  - **데스크톱·태블릿**: 넉넉한 여백 위에 7열 월간 달력 + 선택한 날짜의 기록 요약 패널을 함께 배치한다.
  - **모바일 (`390px` 포함)**: 좁은 7열 칸에 텍스트를 밀어 넣지 않고 포스터/표지 썸네일 중심으로 간결히 보여주고, 날짜 탭 시 하단 시트 또는 아래 일별 목록에서 편하게 상세 이동한다.
  - 작품 상세로 이동했다가 뒤로 돌아오면 보고 있던 **월·필터·선택 날짜·스크롤 위치**를 복구한다.

### 2) 저부담 회상 카드 ("지난 기억 꺼내 보기")
- **노출 조건 (엄격한 비침해 원칙)**:
  - 정해진 과거 구간에 해당하는 **현재 계정의 실제 완료 기록 1건**이 확인될 때만 타임라인에 조용히 표시한다(예: 1개월·6개월·1년은 후보 구간이며 구체적 선택 순서는 구현 전 Web 담당과 확정).
  - 신규 사용자, 최근 기록만 있는 사용자, 진행 중·위시리스트만 있는 사용자, 부분 캐시에 과거 완료 후보가 확인되지 않은 상태에서는 **카드를 노출하지 않는다**(억지 빈 카드 금지).
- **표시 내용과 동작**:
  - 포스터/표지(없으면 제목 대체) + 작품 제목 + 감상 날짜 + 실제 있는 **TPO(장소·상황)**·메모 발췌를 보여준다.
  - 탭하면 해당 작품 상세 및 정확한 수정 이력으로 연결된다. 닫기 버튼으로 부담 없이 숨길 수 있으며 푸시 알림이나 강제 배너를 사용하지 않는다.

### 3) 현지 날짜·시간대 경계 정책 및 검증 예시 ([recordDate.ts](../../apps/web/lib/recordDate.ts))
- 날짜 편집·표시는 **현재 기기의 현지 날짜**를 사용하며, 기존 기록의 날짜를 편집하지 않으면 원래 시각·오프셋을 보존한다. 한국어·영어 언어 설정과 기기 시간대는 독립이다.
- **필수 검증 예시**:
  1. **자정·월말 경계**: `2026-11-30 15:00 UTC`에 저장된 기록은 **서울(KST)** 기기에서는 `12월 1일` 칸에, **로스앤젤레스(PST)** 기기에서는 `11월 30일` 칸에 표시된다. (서울 기준 2026년 11월은 `10월 31일 15:00 UTC` 이상 ~ `11월 30일 15:00 UTC` 미만; LA 기준은 서머타임 해제 포함 `11월 1일 07:00 UTC` 이상 ~ `12월 1일 08:00 UTC` 미만.)
  2. **여행 중 시간대 변경·직접 날짜 입력**: 사용자가 날짜 선택으로 직접 입력한 `2026-11-01`은 현재 기기의 현지 `11월 1일`로 취급해야 하며(UTC 자정 해석으로 미국 서부 기기에서 `10월 31일`로 밀리지 않아야 함), `11월 30일` 기록의 날짜를 `12월 1일`로 수정하고 달력으로 돌아오면 11월 30일 칸에서 빠지고 12월 1일 칸에 반영돼야 한다(다른 기기의 편집·삭제 반영 포함).

### 4) 아직 받지 못한 과거 월(부분 캐시) vs 확정된 빈 달 상태 구분
현행 타임라인은 50건씩 페이지 조회하므로, 첫 50건만 받은 브라우저나 일부 캐시만 남은 오프라인 기기에서 **아직 불러오지 못한 과거 월을 "기록이 없는 빈 달"로 오표시해서는 안 된다.**

| 화면 상태 | 판정 기준 | 기대 안내와 동작 |
| --- | --- | --- |
| **1. 조회 중** | 해당 계정·시간대·월 범위 기록을 서버에서 불러오는 중 | 스켈레톤/조회 중 상태 표시(빈 달 문구 노출 금지) |
| **2. 미확인 / 오프라인 부분 캐시** | 오프라인·조회 실패·월 범위 전체 수신이 끝나지 않아 해당 월이 비었는지 확정할 수 없는 상태 | *"이 기기에 저장된 기록만 표시 중이에요. 이전 기록을 아직 불러오지 못했어요."* 수준의 중립 안내 + 재시도 제공. 이미 기기에 있는 기록은 그대로 보여주되 **빈 달로 단정하지 않음** |
| **3. 확정된 빈 달** | 같은 계정·시간대·월·필터 범위의 전체 조회가 완료되어 실제 기록이 `0건`임이 확인된 상태 | 따뜻한 빈 달 한 문장(*"이달에 남겨둔 기록이 아직 없어요"* / *"No records kept for this month yet"*)과 기존 `기록 남기기` 진입 안내 |

### 5) 브랜드·톤·무압박 정책 ([DESIGN.md](../../DESIGN.md))
- 빈 날짜·빈 달에 "기록 없음"·"연속 기록 끊김"·"목표 미달" 같은 **스트릭·결핍 압박 문구 금지**.
- 크림 배경(`#F8F6F2`), 흰색 카드(`#FFFFFF`), `8px` 모서리를 유지하고, 오렌지(`#FF9933`)는 최종 액션(`기록 남기기`)과 포커스에만 사용(달력 칸·통계에 오렌지 면 채움 금지; 월 이동·선택 날짜·보기 전환은 네이비 `#1E4D8C`와 중립색).

## 완료 조건 (기획 인수 기준)

1. **기존 흐름 보존**: 타임라인 `목록` 보기(검색·필터·스크롤·상세 이동)와 홈의 기존 월별 보기·‘다시 만나는 그날’이 깨지지 않는다.
2. **확정 상태 정책 일치**: 같은 날 완료 영상·진행 중 책·위시리스트가 각 1건 있을 때, 기본 달력은 2건(대표 1장 + `+1`)을 보여주고 위시리스트 필터 선택 시 3건(대표 1장 + `+2`)과 해당 날짜 전체 목록을 제공한다.
3. **시간대·편집 정합성**: 위 자정·월말(서울/LA)·직접 입력·날짜 변경(`11/30`→`12/1`) 및 타 기기 편집·삭제 반영 시 양쪽 월과 날짜 칸이 정확히 갱신된다.
4. **부분 캐시·오프라인 구분**: 50건을 초과한 계정이나 오프라인 부분 캐시 기기에서 미조회 과거 월이 "빈 달"로 오표시되지 않으며, 전체 조회가 끝난 빈 달에서만 빈 달 안내가 표시된다.
5. **회상 카드 정확성**: 과거 완료 기록이 없는 조건(신규·최근 기록만·진행 중/위시리스트만·부분 캐시 후보 없음)에서는 노출되지 않고, 실제 후보가 있을 때만 정확한 작품 상세·수정 이력으로 이동하며 닫기 동작이 유지된다.
6. **접근성·반응형·KO/EN**: 한·영 모바일(`390px`)·데스크톱, 키보드 탐색(월 이동·날짜 이동·Enter 선택·Escape 닫기·포커스 복귀), 스크린 리더 날짜/건수 안내, `prefers-reduced-motion`, 상세→뒤로가기 복귀가 정상 동작한다.

## 단계별 플랫폼 범위 (1단계 vs 후속)

| 단계 | 대상 | 포함 범위 |

- **착수 판단.** API #171과 Web #162의 운영 검증, API·Web의 기술 검토를 마쳤다. 본부는 #182와 Windows #161·Apple #163의 안전성 결과를 [다음 사이클 #158](https://github.com/chawon/ott/issues/158#issuecomment-7162888057)에서 확인한 뒤 Web 구현 착수를 결정한다.
- **되돌림 조건**: 기존 목록 타임라인과 분리된 보기 전환으로 제공해 기록·동기화 데이터에 영향을 주지 않는다. 성능 저하나 4주 관찰 후 활용도 미흡 시 `달력` 전환과 회상 카드 노출을 제거해 즉시 복구할 수 있다.
- **1단계 성공 지표 (Web/PWA 출시 후 완료된 28일 KST, 관리자·테스트 제외, `#169`·`#179` 확정 정의 기준)**:
  - **자기 선택 편향 분리**: 달력 조회자와 비조회자의 단순 재방문율 비교로 인과를 단정하지 않는다.
  - **달력 탐색 지표** *(분모: 달력 진입이 노출된 Web/PWA 사용자 기준 · 현재 `미측정`)*:
    - 달력 열기 도달률, 월 이동 비율, 날짜 선택 비율 (리렌더·뒤로 복귀 중복 집계 제외)
  - **회상 카드 이용 지표** *(분모: 과거 완료 기록을 보유해 회상 카드 노출 자격을 충족한 Web/PWA 사용자 기준 · 현재 `미측정`)*:
    - 회상 카드 상세 진입률 = 관찰 기간에 회상 카드를 통해 해당 기록의 상세를 한 번 이상 연 고유 사용자 수 ÷ 같은 기간에 회상 카드 노출 자격을 충족한 Web/PWA 고유 사용자 수
  - **반복 기록 관찰**: 도입 전후 동일 기준(관리자 제외, 완료된 주간 코호트) 비교 또는 제한 노출 실험으로 2~4주차 재기록 추이 확인(표본이 작으면 절대 건수와 표본 한계 병기).
  - *(후속 지표 분리)*: 월간 달력 공유 이미지 생성·공유 계측과 마케팅 공유 유입 안내는 공유 기능을 추가하는 후속 단계에서 별도 정의한다.
