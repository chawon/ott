# 공통 기능 기준과 플랫폼별 차이

초기 기준일은 2026-11-22다. Web·API의 [운영 `c693fd8`](web-api-rollout-2026-11-22.md) 반영을 갱신했으며 네이티브·스토어는 각 근거를 유지한다. 이 문서는 목표 지원 범위와 확인된 차이를 관리한다. 앱 버전·공개 상태는 [플랫폼 현황](platforms.md), 세부 데이터 의미는 [공통 계약](product-contracts.md)을 따른다. 전체 플랫폼의 실제 기능 감사는 Project V2 권한 없이 열 수 있는 [기획 이슈 #157](https://github.com/chawon/ott/issues/157)에서 진행한다.

## 기록 방식

정책과 반영 상태를 두 축으로 기록한다.

| 축 | 값과 의미 |
| --- | --- |
| 목표 지원 범위 | **공통 필수**: 해당 기능을 지원하는 앱의 결과·데이터 의미를 맞춘다. **플랫폼 특화**: OS·입력·화면에 맞춘 확장이다. **명시적 미지원**: 해당 채널의 역할 밖이며 사유가 있다. **종료**: 제거와 이전 앱 호환을 추적한다. |
| 실제 반영 상태 | **미확인**, **대기**, **구현 중**, **PR 검증**, **병합**, **배포/심사**, **공개 확인**, **실사용 확인**. 각 값에 기준 SHA·버전·날짜 또는 근거 링크를 붙인다. |
| 차이 판정 | **허용된 차이**: 제품/플랫폼 사유가 합의됐다. **추가 반영 필요**: 공통 목표를 아직 충족하지 못했다. **확인 필요**: 근거가 부족하다. **종료 이행 중**: 이전 설치판과 호환하며 제거한다. |

`미확인`을 미지원으로 처리하지 않는다. PR 병합을 공개 출시로 처리하지 않는다. 프로젝트 카드의 네 가지 상태는 업무의 진행을 나타내며 위 반영 근거를 카드 본문에 함께 남긴다.

## 채널별 지원 범위 기준

| 대상 | 함께 유지할 경험 | 플랫폼에 맞춰 확인할 부분 |
| --- | --- | --- |
| Web/PWA | 기록·수정 이력·계정 연결·동기화·공개 대화의 공통 의미 | 창 폭·키보드/터치, 브라우저 저장소, 설치형 PWA 캐시·재진입·오프라인 범위 |
| Android 폰·태블릿 | 같은 계정·기록·동기화·함께 동작 | 폰/태블릿·폴더블의 화면 전환, OS 권한·알림·기존 TWA 복구 |
| iPhone | 같은 계정·기록·동기화·함께 동작 | 작은 화면·OS 공유/확장과 이전 Expo 설치판 업데이트 |
| iPad | iPhone과 같은 데이터·행동 결과 | 가로/세로·Split View·2단 탐색과 선택 상태 |
| macOS | 같은 기록·연결·함께의 의미 | 큰 창·키보드·메뉴 막대·Spotlight·브라우저 이어받기 |
| Windows | 같은 기록·연결·함께의 의미 | 큰 창·키보드·스토어 패키지·브라우저/PWA 이어받기 |
| Chrome·Edge·Whale 확장 | Web/앱 빠른 기록으로 제목·플랫폼을 전달하는 보조 진입 | 브라우저 권한·패키지·기존 세 스토어 게시·설치 결과. 전체 기록 앱의 화면 집합을 요구하지 않는다. |
| 토스 인앱 | 채널 전략에 정한 검색·기록·타임라인과 연결의 핵심 흐름 | 별도 공개 번들·인앱 환경. 추가 기능은 해당 채널의 채택 범위를 먼저 정한다. |
| ChatGPT 앱 | 재개 시 기존 ottline 기록의 읽기 전용 연결 계약 | 현재 미운영 채널이다. 쓰기·전체 앱 UI는 지원 범위에 포함하지 않는다. |

상세 채널 범위는 [확장·토스·ChatGPT 전략](changes/v2-channel-strategy.md)을 따른다. Web과 PWA, Android 폰과 태블릿처럼 소스를 공유하는 대상도 설치·화면·캐시·OS 조건이 다르면 검증 근거를 나눈다.

## 기능별 공통 기준

| 기능 | 함께 유지할 의미·완료 결과 | 차이와 검증에서 확인할 것 |
| --- | --- | --- |
| 검색과 작품 선택 | 기존 작품·시즌·책 판본 ID를 보존하고 언어/출처 계약을 따른다. | 검색 제공자 capability·출처 표시와 KO/EN, 이전 앱 호환 |
| 기록 저장·수정·이력 | 상태·감상 시점·TPO·느낌 등 저장 필드와 수정 이력의 의미를 맞춘다. | 폼 배치·입력 방식은 플랫폼에 맞추고 저장 후 결과를 대조 |
| 계정·기기 연결 | 같은 계정의 기록을 이어 쓰며 기존 데이터와 미동기화 변경을 보존한다. | 코드 입력·복구·브라우저 이어받기·최초/기존 설치와 실패 후 재시도 |
| 동기화·오프라인 | 로컬 우선 저장, outbox, 중복 방지·충돌 복구 계약을 유지한다. | 앱별 실제 오프라인 사용 범위와 재접속 검증. 정적 안내 제공과 기록 사용 범위를 각각 확인 |
| 함께 목록·상세·댓글·반응 | 선택한 이야기와 댓글·반응 대상이 일치하고 기존 상세 링크가 이어진다. | 작은 창은 목록→상세, 큰 창은 목록/상세 동시 표시. 검색·선택·스크롤·뒤로가기 상태 |
| 함께 큐레이터 종료 | 신규 질문 생성·게시를 종료하고 개인 기록·대화·댓글은 보존한다. | 구형 앱의 빈 배열 응답, 플랫폼별 fallback과 질문 UI 제거 |
| 리포트·서가·공유 | 같은 기록을 기준으로 해석하며 공유 내용의 의미를 맞춘다. | 집계 구간·언어·분류 capability·OS별 저장/공유와 미지원 범위 |
| 삭제·초기화 | 사용자용 개별 기록 삭제를 제공하지 않고, 로컬 초기화와 계정 전체 삭제를 구분한다. | 실제 제공 액션, 서버 성공/실패 시 데이터 보존과 설치판 검증 |
| 기기 표기·계측 | 기기를 구분해 표시하면서 기존 플랫폼/계정 집계 계약을 보존한다. | 폰/태블릿 표기와 OS·런타임·물리 기기 수의 의미를 구분 |
| 언어·접근성·상태 안내 | KO/EN, 조회 중·진짜 부재·오류·저장/전송 상태의 의미를 맞춘다. | 표현·레이아웃·OS 조작은 현지화/접근성 기준으로 검증 |

이 표는 지원 범위의 기준이다. 기능마다 전체 앱·보조 채널에 대한 채택/제외를 변경안에 명시하고 실제 반영 상태를 붙인다.

차이마다 **영향 사용자·기능, 목표 지원 범위, 현재 버전/근거, 허용 사유 또는 부족한 동작, 담당·관련 카드, 재검토 시점/조건**을 남긴다. 기획 담당은 차이 대장을 관리하고 본부가 담당별 반영과 공통 완료를 판정한다. 이후 감사와 PR·출시 결과가 쌓이면 위 초기 항목의 근거를 갱신한다.
