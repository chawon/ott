# 플랫폼 간 변경안 작성

새 기능, 정책 또는 공통 계약을 바꿀 때 이 폴더에 `기능명.md`를 만든다. 소규모 변경은 같은 항목을 기존 설계 문서나 이슈에 기록하고 코드 PR과 연결해도 된다. 작업 전에 [플랫폼 현황](../platforms.md)과 [공통 API와 데이터 계약](../product-contracts.md)을 확인한다.

1. 해결하려는 사용자 문제와 공통 동작을 정의한다. 영상·책, 한국어·영어, 신규·기존 사용자의 차이가 있으면 기록한다.
2. 영향받는 플랫폼마다 변경, 구현 위치, 출시 방식, 확인 조건을 적는다. 영향이 없는 플랫폼은 사유를 짧게 기록한다. Web과 PWA가 소스를 공유해도 설치 상태와 캐시가 관련되면 별도로 확인한다.
3. 서버/API와 데이터를 먼저 결정한다. 이전 바이너리와의 호환 기간, 로컬 저장소·동기화·기기 연동, 기존 사용자 데이터의 마이그레이션과 되돌릴 수 있는 범위를 기록한다.
4. 플랫폼 PR과 검증 결과를 모아 문서를 갱신한다. 반영된 커밋, CI·패키지, 스토어 제출 및 실제 출시, 실기기 확인의 단계별 근거를 남긴다.

## 복사용 양식

```markdown
# 변경 이름

## 사용자 문제와 완료 조건
- 현재 동작, 변경 후 기대 동작, 범위
- 동작을 확인할 시나리오와 결과

## 공통 계약
- API·필드·기본값, 인증과 데이터 변경
- 이전 설치 앱과 호환, 로컬 저장·동기화·마이그레이션
- 검토한 대안과 결정 근거

## 플랫폼별 반영
| 대상 | 변경과 소스 경로 | 검증 조건 | 상태와 근거 |
| --- | --- | --- | --- |
| API | | | |
| Web/PWA | | | |
| Android | | | |
| iOS (출시 Expo와 개발 SwiftUI 확인) | | | |
| Windows | | | |
| macOS | | | |
| 확장 프로그램 | | | |
| 토스 인앱 | | | |

## 출시와 복구
- 선행 변경과 적용 순서
- 배포 SHA·스토어 버전·실행 및 검증 링크
- 기존 데이터 보존, 되돌리는 조건과 방법, 남은 확인
```
