## 사용자 문제와 완료 조건

### 현재 동작과 문제
- 현재 ottline의 개인 타임라인은 세로 목록 중심이고, 리포트는 숫자·요약 중심이다([feature-matrix.md](../feature-matrix.md)).
- 기록을 쌓아둔 사용자가 **"이번 달에 내가 무엇을 보고 읽었지?"**를 한눈에 돌아보거나, 몇 달·1년 전에 남긴 기억(포스터·표지·TPO·메모)을 자연스럽게 다시 마주할 계기가 부족하다.
- [DESIGN.md](../../DESIGN.md)가 정의한 ottline의 정체성(*"생산성 대시보드가 아니라 손때 묻은 기억의 서가, 포스터와 표지가 기억의 닻"*)을 가장 직관적으로 체감할 수 있는 월간 회상 뷰가 전 플랫폼에 없다.

### 검증할 가설
- **가설**: 기존 목록 타임라인을 해치지 않으면서 ① 영상·책 포스터/표지가 날짜 칸에 담기는 **월간 기록 달력**과 ② 과거 기록이 있는 사용자를 위한 비침해형 **저부담 회상 카드**를 제공하면, "새로 기록할 때만 여는 앱"에서 "기억을 돌아보기 위해 다시 여는 앱"으로 사용 맥락이 확장되어 2~4주차 반복 기록 및 자발적 공유에 긍정적 영향을 줄 것이다. *(경쟁사 기능 관찰만으로 효과를 단정하지 않고 출시 후 지표로 검증한다.)*

### 기대 사용자 흐름 (핵심 경험 3가지)

#### 1) 월간 기록 달력 (타임라인 내 `목록 | 달력` 보기 전환)
- **진입 위치**: 기존 `타임라인` 상단에 `목록 | 달력` 보기 전환을 둔다. 기존 목록 흐름과 필터를 깨지 않는다.
- **콘텐츠 필터 연동**: 기존 타임라인의 `전체 / 영상 / 책` 필터와 연동한다(예: `전체`면 영상+책 통합 달력, `책`이면 독서 달력).
- **날짜 배치 기준**: 기록 생성/수정 시각이 아니라 사용자가 남긴 **감상·독서 날짜(`watchedAt`)**를 기준으로 해당 날짜 칸에 배치한다.
- **하루에 여러 기록(2건 이상)이 있는 날**:
  - 날짜 칸에는 대표 포스터/표지 1장을 깔끔하게 보여주고 작은 건수 표기(예: `+2`)로 여러 건이 있음을 알린다.
  - 대표 이미지 우선순위: **포스터/표지가 있는 완료 기록 우선 → 최신 기록 순**.
  - 해당 날짜를 선택하면 그날 남긴 전체 기록(포스터/표지, 제목, 상태, **TPO(장소·상황)**, 메모)을 한눈에 보고 작품 상세·수정 이력으로 이동할 수 있다.
- **포스터/표지가 없는 작품**: 깨진 이미지나 빈칸으로 두지 않고, 따뜻한 중립 표면 위에 짧은 제목이 읽히도록 표시한다.
- **메모가 없는 기록 처리**: `.omd/preferences.md` 원칙에 따라 메모 없는 기록도 온전한 기록으로 취급하며, 달력/일별 요약에서 "메모가 없어요" 같은 결핍 문구를 반복 노출하지 않는다.
- **데스크톱·태블릿 vs 모바일 경험 분리 (`.omd/preferences.md` 기준)**:
  - **데스크톱·태블릿**: 넉넉한 여백 위에 7열 월간 달력과 선택한 날짜의 기록 요약 패널을 함께 보여줘 탐색 맥락을 유지한다.
  - **모바일**: 좁은 7열 칸에 텍스트를 밀어 넣지 않고 **포스터/표지 썸네일 중심**으로 간결하게 보여준다. 날짜를 탭하면 하단 시트 또는 아래 영역에 그날의 기록 카드(제목·상태·TPO·메모)가 열려 터치로 편하게 상세 이동할 수 있다.

#### 2) 저부담 회상 카드 ("지난 기억 꺼내 보기")
- **노출 조건 (엄격한 비침해 원칙)**:
  - 일정 기간 이상 지난 과거 완료 기록이 실제로 존재하는 사용자에게만 조용히 표시한다(예: 1년 전·6개월 전·1개월 전 같은 주/같은 달에 남긴 기록 1건).
  - 과거 기록이 없는 신규·초기 사용자에게는 **아예 노출하지 않는다**(억지 빈 카드·안내 배너 금지).
- **표시 내용**: 포스터/표지 + 작품 제목 + "1년 전 이맘때 남긴 기록"(KO/EN) + 당시 **TPO(장소·상황)**·느낌·짧은 메모 발췌 → 탭하면 기존 작품 상세·수정 이력으로 이동해 다시 보거나 새 느낌을 이어 적을 수 있다.
- **부담 없는 제어**: 푸시 알림 강요나 닫기 불가 고정 배너를 두지 않고, 크림 틴트(`#FEF9EE`) 카드로 조용히 닫거나 넘길 수 있게 한다.

#### 3) 월간 달력 공유 카드 *(1단계 포함 여부 — 사용자 정책 확인 항목)*
- 기존 주간·월간 리포트 공유 카드([weekly-report-share-card-posters.md](../weekly-report-share-card-posters.md))와 같은 결로, 사용자가 원할 때 현재 보고 있는 월간 포스터 달력을 저장·공유 가능한 이미지로 만든다.
- **프라이버시 원칙**: 개인 프로필·연결 코드·상세 메모를 자동 노출하지 않으며, 해당 월 표기·포스터/표지 달력·기록 건수 등 공개해도 부담 없는 정보만 담는다.

### 브랜드·톤·무압박 정책 ([DESIGN.md](../../DESIGN.md) 기준)
- **죄책감·스트릭 압박 금지**: 빈 날짜 칸에 "기록 없음"·"연속 기록이 끊겼어요"·"이번 달 목표 미달" 같은 압박 문구나 스트릭 카운터를 절대 넣지 않는다.
- **빈 달 안내 (KO/EN)**: 기록이 없는 달에는 따뜻한 한 문장(예: *"이달에 남겨둔 기록이 아직 없어요"* / *"No records kept for this month yet"*)과 기존 `기록 남기기` 진입만 조용히 제공한다.
- **색상 위계 준수**: 크림 배경(`#F8F6F2`) 위 흰색 카드(`#FFFFFF`)·`8px` 모서리를 유지하고, 오렌지(`#FF9933`)는 최종 액션(`기록 남기기`·`달력 공유`)과 포커스에만 사용한다. 선택된 날짜·월 이동·보기 전환은 네이비(`#1E4D8C`)와 중립색을 사용하며 달력 칸·통계에 오렌지 면 채움을 쓰지 않는다.

### 완료 조건 (기획 인수 기준)
1. 기존 타임라인 `목록` 보기의 검색·필터·스크롤·상세 이동 동작이 전혀 깨지지 않는다.
2. `목록 | 달력` 전환 시 현재 선택된 `전체 / 영상 / 책` 필터와 기록 데이터가 일관되게 반영된다.
3. 하루 1건·하루 다건(`+N`)·포스터 없음·메모 없음·빈 달·과거 연도/월 이동 모든 상태에서 레이아웃 깨짐이나 압박 문구가 없다.
4. 날짜를 선택해 기록을 열면 기존 작품 상세·수정 이력 화면으로 정확히 연결되며, 수정 후 돌아왔을 때 달력 상태도 일치한다.
5. 과거 기록이 없는 사용자에게는 회상 카드가 노출되지 않고, 과거 기록이 있는 사용자에게만 정확한 날짜·TPO·작품으로 연결된다.
6. 한국어·영어(KO/EN), 데스크톱·모바일(390px 포함), 키보드/접근성 탐색과 `prefers-reduced-motion`에서 정상 동작한다.

## API·Web 담당 기술 검토 요청 항목 (착수 전 선행 관문)

1. **과거 월 기록 조회 범위**: 현재 로컬 저장소와 키셋 페이징(`/api/logs/page`)만으로 사용자가 6개월~1년 전 달로 이동했을 때 누락 없이 표시할 수 있는지, 또는 월/기간 단위 조회 보완이 필요한지 확인.
2. **달력 썸네일 성능·오프라인 동작**: 한 달에 수십 건의 포스터/표지가 표시될 때 로딩 성능, 기존 포스터 캐시 및 오프라인 상태의 로컬 표시 확인.
3. **월간 달력 공유 이미지 범위**: 1단계에 포함할 경우 기존 공유 카드 생성 경로(`/og/share-card` 등) 재사용 가능성과 리소스 비용 확인.
4. **탐색 계측 정합성 ([`#169`](https://github.com/chawon/ott/issues/169) 연계)**: `calendar_open`, 월 이동, 날짜 선택, 회상 카드 클릭, 월간 공유 카드 생성 이벤트를 `#169` 공통 계측 기준과 충돌 없이 정의.

    - 달력 도달: `calendar_open` 고유 actor / `qualifiedActors`
    - 회상 행동: 달력 내 월 이동·날짜 선택·회상 카드→상세 진입 비율
    - 공유 행동(포함 시): 월간 달력 공유 카드 생성 수
  - **반복 기록 관찰**: 도입 전후 동일 기준(관리자 제외, 완료된 주간 코호트) 비교 또는 제한 노출 실험으로 2~4주차 재기록 추이 확인(표본이 작으면 절대 건수와 표본 한계 병기).
  - **마케팅 연계**: 월간 달력 공유 카드가 포함되면 [마케팅 운영](../marketing-operations.md)의 출시 안내·공유 유입 실험과 실제 지원 플랫폼(1단계 Web/PWA) 범위를 맞춰 연결한다.

## 사용자(제품 오너) 정책 확인이 필요한 항목 2가지

1. **달력에 `보고 싶어요 / 읽고 싶어요`(위시리스트) 기록을 기본 포함할지 여부**:
   - *안 A (기획 추천)*: 기본 달력에는 실제 감상·독서 기억인 **`봤어요/읽었어요`·`보는 중/읽는 중`**만 보여주고, 위시리스트(`보고 싶어요/읽고 싶어요`)는 달력 기본 보기에서 제외(원하면 필터로 선택).
   - *안 B*: 날짜가 있는 모든 상태(`보고 싶어요/읽고 싶어요` 포함)를 달력에 함께 표시.
2. **1단계 Web/PWA MVP에 `월간 달력 공유 이미지`를 함께 넣을지 여부**:
