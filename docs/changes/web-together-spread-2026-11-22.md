# Web/PWA 함께 목록·상세와 큐레이터 종료

2026-11-22 [제품 기획 운영](../product-planning.md)과 [기능 기준표](../feature-matrix.md)에 맞춰 Web/PWA의 세 실행 카드를 함께 구현한다. 공통 기능의 출시 완료는 본부가 각 플랫폼 근거로 판단한다. 이 문서는 Web 변경과 검증만 기록하며 [공통 계약](../product-contracts.md)을 복제하지 않는다.

## 구현 결정과 호환성

- App Router의 공유 `public/layout.tsx`가 실제 사용자 목록을 서버에서 먼저 읽는다. 클라이언트는 목록을 새로 조회하며, 같은 layout을 유지해 경로 이동 중 검색·정렬과 왼쪽 스크롤을 보존한다. 상세 링크를 다른 형태의 쿼리 URL로 바꾸지 않는다.
- 실제 본문 컨테이너가 52rem 이상일 때 CSS container query로 2단을 연다. 창 폭이 줄면 동일한 컴포넌트를 작은 화면 흐름으로 표시한다. 양쪽은 따로 스크롤하며 키보드 순서는 목록→상세다.
- 상세 조회를 명시적인 상태로 나누고 `ApiError.status`로 404를 판별한다. 기존 오류 메시지 형식은 유지한다. 선택이 바뀌면 상세 컴포넌트를 새로 만들고 이전 요청을 취소해 늦은 응답·댓글이 새 작품에 섞이지 않게 한다. 새 상세 제목으로 포커스를 옮기며 선택 링크에 `aria-current`를 붙인다.
- 큐레이터 목록/작성 컴포넌트와 번역·타입·귀속 저장 코드를 제거한다. 기존 브라우저 귀속 값은 더 이상 읽지 않으며 로컬 기록·인증·사용자 저장소를 초기화하지 않는다. 관리자 전용 작성 화면은 `/admin`으로 돌려보내고 전용 통계 조회/영역을 제거한다. 과거 이벤트가 기본 사람 지표에 섞이지 않도록 기존 필터는 보존한다.
- 관리자 BFF의 이력 GET은 기존 Cloudflare Access·서버 토큰·비캐시 경계를 유지한다. 옛 생성/게시/비활성화 POST는 Access 인증과 기존 Origin/JSON 검증을 거친 후 HTTP 410으로 종료하며 서버로 전달하지 않는다.
- API 종료 계약은 [API PR #150](https://github.com/chawon/ott/pull/150)에 있다. 이전 앱의 공개 배열 GET 200 `[]`, 인증 후 관리자 쓰기 410, 기존 데이터·이력 보존을 전제로 한다. Web은 종료된 공개 목록을 조회하지 않는다. DB 스키마나 사용자 기록 계약은 바꾸지 않는다.

## 검증 근거

- 기존 production 빌드에서는 JavaScript를 끈 KO 상세 DOM에 잘못된 부재가 한 번 나타나 같은 회귀 검증이 실패하는 것을 확인했다. 새 빌드는 세 신고 링크 모두 처음에 조회 중을 표시하며 부재를 표시하지 않는다.
- `npm run test:together-runtime --workspace ott`: 실제 Next production UI와 임시 로컬 API/IndexedDB를 연결해 KO/EN 총 20개 시나리오를 확인한다. SSR 목록, 세 링크 직접 진입/새로고침, 키보드, 2단, 검색·정렬·선택·스크롤·뒤로가기, 320/390/768/895/896/1024/1440 폭, 느린 응답/선택 경합, 404/503/재시도, 댓글 등록·반응과 대기 outbox, 반응 취소 후 기록 보존, 큐레이터 조회/이벤트 부재를 포함한다. 기존 큐레이터 응답을 일부러 제공하고 옛 귀속 값을 미리 저장한다. 모든 요청은 격리 API로 제한하며 운영 데이터는 사용하지 않는다.
- 기존 관리자 경계 15개, SEO 20개, analytics 10개, 타입 검사와 Next.js production build 통과. 변경 파일 Biome은 기존 일반 이미지 관련 경고와 QuickLog의 기존 단언 경고를 제외하고 오류가 없다.
- 브라우저 회귀는 Verify Web CI에 추가한다. KO/EN 큰 화면/작은 화면 캡처와 로컬 결과는 `/tmp/ottline-together-qa`에 남긴다. 공개 운영 API·배포된 번들·실제 설치형 PWA 검증으로 해석하지 않는다.

## 출시와 복구

기준 소스는 `37eda7f`이며 최종 PR은 본부의 기획 문서가 추가된 최신 main과 통합해 검토한다. 실제 head·PR·CI는 각 실행 카드에 남긴다. 코드·CI 통과만으로 카드를 완료하거나 공개 출시로 표시하지 않는다.

API 종료 PR 반영 → 실제 KO/EN GET 200 `[]`와 인증 후 쓰기 410·일반 문의/DailyReport 확인 → **동일 병합 SHA의 Web** 순서다. 배포 SHA·이미지·APP_VERSION과 실제 상세 세 링크·함께 목록을 본부/운영 담당이 확인한 뒤 설치형 PWA의 기존/신규 설치·재진입을 확인한다.

실패 시 이전에 검증한 Web 이미지로 되돌릴 수 있다. API의 빈 배열 호환과 기존 DB/승인 이력 보존을 유지하고 큐레이터 자동화 재개는 별도 판단한다. 로컬 데이터 삭제나 DB 정리는 복구 절차에 포함하지 않는다.
