## 재개 조건 (언제 다시 검토하는가)

아래 중 하나 이상이 충족될 때 우선순위를 재검토한다:
1. 국내 주요 기록 서비스(왓챠피디아·북모리·북적북적 등)의 **공식·안정적 사용자 파일 내보내기 포맷**이 확인되고, 국내 사용자 문의·전환 수요가 누적될 때
2. 영어권 등 **해외 이용자 유입이 유의미하게 증가**해 Letterboxd·Goodreads·StoryGraph 가져오기 수요가 생길 때
3. ottline 자체 내보내기 파일의 **식별자·메타데이터 보강**(작품 ID·ISBN·시즌/회차 포함)이 함께 검토되어 신뢰할 수 있는 백업/복원 루프를 만들 시점이 될 때

## 사용자 문제와 완료 조건

### 현재 동작과 문제
- 현재 ottline은 [timeline-export.md](../timeline-export.md) 기반의 Web/네이티브 CSV 내보내기와 Windows 앱의 Netflix CSV 가져오기만 제공한다.
- 타 서비스에 기존 감상·독서 기록을 쌓아둔 사용자가 ottline으로 옮겨오려 할 때 기존 기록을 수동으로 다시 입력해야 하는 전환 장벽이 존재한다.

### 기대 사용자 흐름 (4단계 — 재개 시 공통 기준)
1. **파일 선택 (로컬 파일 업로드)**: 검증된 지원 포맷 안내를 보고 사용자가 직접 내려받은 CSV 파일을 선택한다.
2. **매칭 결과 미리보기 (저장 전 검토 필수)**: 전체 행 수, `새로 추가될 기록` / `이미 있는 기록(기본: 건너뛰기)` / `후보 확인 필요` / `매칭 실패`를 명확히 구분해 보여준다.
3. **사용자 선택·확정**: 사용자가 동명·복수 판본 후보를 직접 확인하거나 항목을 제외한 뒤 명시적으로 `가져오기 실행`을 누른다.
4. **안전한 반영 및 결과 요약**: 개인 타임라인에만 저장되며(자동 공개 금지), 성공·건너뜀·실패 건수와 재현 한계를 요약 안내한다.

### 완료 조건 (기획 인수 기준)
1. 사용자가 미리보기에서 확정하기 전에는 실제 기록이 1건도 저장되지 않는다.
2. 기존 ottline 기록이 있는 작품·책 판본에 대해 기본값으로 덮어쓰기가 발생하지 않으며, 기존 메모·TPO·수정 이력이 보존된다.
3. 가져온 기록은 어떤 경우에도 `함께` 공개 대화나 공개 댓글로 자동 게시되지 않는다.
4. 동일 파일을 다시 업로드하거나 진행 중 중단 후 재시도해도 중복 기록이 생성되지 않는다.
5. 대량 가져오기 도중/직후에도 사용자의 일반 기록 저장·수정·동기화 흐름이 멈추지 않는다.
6. 한국어·영어(KO/EN)에서 지원 포맷 안내, 미리보기 상태, 재현 한계 및 건너뜀/실패 안내가 자연스럽게 제공된다.

## 현재 ottline 자체 Web CSV의 재현 범위와 보존 한계

현재 Web CSV 내보내기([apps/web/lib/export.ts](../../apps/web/lib/export.ts))는 언어별 번역 헤더와 표시 문자열 9개 컬럼(`watchedAt`, `type`, `title`, `status`, `rating`, `place`, `occasion`, `ott_or_platform`, `note`)만 출력하며, **작품 ID(`titleId`·`provider`·`providerId`), 책 판본 `ISBN`, 시리즈 `시즌·회차`, 과거 수정 이력(`history`), 스포일러 여부, 날짜 이하 시각(타임스탬프)은 포함하지 않는다.**

따라서 **현재 Web CSV 파일만으로 원본 기록·판본·이력의 완전한 복원을 약속할 수 없다.** 기존 KO/EN Web CSV를 재가져오기로 지원할 경우 아래 경계를 화면에 투명하게 고지한다:

| 구분 | 범위 |
| --- | --- |
| **재현 가능한 정보** | 날짜(`YYYY-MM-DD`), 분류(영화/시리즈/책), 제목 텍스트, 상태, 평점, 장소·상황(TPO), 플랫폼, 메모 |
| **보존 한계 (재현 불가)** | 원래 작품/외부 식별자(`titleId`/`providerId`), 책 판본 `ISBN`, 시리즈 시즌·회차, 과거 수정 이력, 스포일러 여부, 정확한 시각 |
| **동명 작품·복수 판본 처리** | 제목·분류만으로 같은 제목·저자의 서로 다른 판본을 자동 정확 매칭하지 않는다. **동명·복수 판본 후보는 반드시 `후보 확인 필요` 또는 `건너뛰기`로 처리**한다. |

> 완전한 백업·복원이 목표라면, 가져오기 구현 전에 **내보내기 포맷에 작품/판본 식별자(ID·ISBN·시즌/회차)를 포함하는 사전 변경**을 별도로 검토해야 한다.

## 지원 포맷 범위와 플랫폼 차이 (재개 시 검토 기준)

- **국내 우선 검토 (실제 공식 내보내기 검증 선행)**: 현재 주 이용자 비중을 고려해 국내 서비스(왓챠피디아·북모리·북적북적 등) 및 Netflix 시청 기록 CSV의 공식 내보내기 가능 여부·최신 컬럼 구조를 먼저 확인한다.
- **글로벌 포맷 (해외 유입 확대 시)**: Letterboxd CSV, Goodreads / StoryGraph CSV.
- **자체 Web CSV**: 위 보존 한계(부분 재현·동명/복수 판본 확인 필수)를 명시한 조건부 지원 또는 내보내기 메타 보강 후 지원.
- **영구 제외 범위**: 타 서비스 계정 ID/비밀번호 입력 대행, 비공식 크롤링/스크래핑 방식은 프라이버시·약관 충돌로 지원하지 않는다.
- **플랫폼별 지원 범위**: 재개 시 1단계 **Web/PWA 우선**(큰 화면 파일 선택·다건 미리보기 검토 후 기존 동기화로 네이티브 반영), 2단계 네이티브 확장 여부 재검토. 확장·토스·ChatGPT는 명시적 미지원.

## 제품 정책과 필수 안전장치 (기획 요구사항)

> 파싱 위치·매칭 API·배치 크기·outbox/동기화 제어는 API·플랫폼 담당의 기술 설계 범위다.

1. **개별 삭제 없음 정책 하에서의 사전 안전장치**: ottline은 사용자용 개별 기록 삭제를 제공하지 않으므로([AGENTS.md](../../AGENTS.md)), 저장 전 미리보기(Dry-Run) 확정 없는 즉시 가져오기를 금지하고 회당 안전한 건수 상한을 둔다.
2. **매칭 3그룹 투명 분리**: `정확 매칭`(고유 식별자·ISBN 일치 등) / `후보 확인 필요`(동명·복수 판본 — 자동 임의 확정 금지) / `미매칭`(기본 건너뛰기).
3. **중복 기본값 = 기존 기록 유지**: 이미 같은 작품·판본 기록이 있으면 기존 메모·TPO·상태·수정 이력을 덮어쓰지 않고 건너뛴다.
4. **공개 범위 · 계측 분리**: 100% 개인 타임라인 저장(자동 `함께` 공개 금지). 대량 가져오기가 일상 `log_create`·`first_log_create` 지표를 왜곡하지 않도록 `#169`와 맞춰 가져오기 전용 이벤트로 분리한다.
5. **미래의 타임라인 추천 자격 (재개 시 사용자 결정 항목)**: 가져온 완료 기록을 추천 자격(5건)과 취향 입력에 포함할지 여부는 착수 전 최종 확인한다.

## API·플랫폼 담당 기술 검토 요청 항목 (재개 시 선행)

1. 대량 작품/도서 매칭 시 외부 검색 API(TMDB·Kakao·Google Books) 호출 한도·응답 지연 및 캐시 활용 범위
2. 대량 저장 시 로컬 우선 outbox·동기화 부하와 중단/재시도 시 중복 방지 보장 방식
3. 동일 파일 내 다중 날짜(재감상/재독) 행과 수정 이력 모델 호환성
4. 가져오기 전용 계측 정의와 `#169` 공통 계측 정합성
