## CI와 검색 입력 후속 반영 (2026-11-05)

CI는 [통합 문서](ottline-ci-v2-integration.md)와 [자산 문서](ottline-ci-v2.md)에 정리했다. 새 책·재생 심벌과 크림 톤을 사용하면서, `ottline` 이름과 부제는 사용자가 선호한 기존 Pretendard 글자체·굵기·자간을 복원했다. 웹 헤더·파비콘·PWA·공유 미리보기와 가이드·설치 안내 화면 이미지를 같은 방향으로 맞췄다. 네이티브 앱 아이콘용 원본과 레이어는 준비했으며 바이너리·스토어 배포는 별도다.

작품 검색은 한글을 입력하다 띄어쓰기를 눌러야 후보가 나오는 현상을 수정했다. IME Enter 오선택 방지를 추가하면서 검색 effect까지 `composing` 상태로 막은 것이 원인이었다. 검색은 조합 중에도 현재 입력값을 250ms debounce로 조회하고, `isComposing`·조합 상태·keyCode 229의 키보드 선택 보호는 유지한다. 조합 종료만으로 같은 검색을 중복 실행하지 않는다.

새 회귀 검사는 실제 검색 모달에서 `compositionstart`와 `insertCompositionText` 입력을 보내고, **띄어쓰기·compositionend 전에** `인셉` → `인셉션`의 검색 요청과 후보가 갱신되는지 확인한다. 수정 전 같은 명령으로 두 번 실패했고, 수정 후 모바일·PC × 전체·영화·책 6개 조건에서 통과했다. API는 모두 격리하며 실제 계정·기록·공개 글은 생성하지 않는다. 기존 기록 모달 검사도 실제 개발 검색 API에서 IME Enter·뷰포트·입력 요소 유지·포커스 가두기·닫기 후 복귀를 통과했다.

```sh
WEB_RUNTIME_URL=http://127.0.0.1:4173 node apps/web/scripts/test-title-search-ime.mjs
WEB_RUNTIME_URL=http://127.0.0.1:4173 node apps/web/scripts/test-recording-dialog.mjs
```

기존 검사는 IME Enter가 작품을 선택하지 않는지만 확인해 검색 자체의 중단을 놓쳤다. 새 검사는 조합이 끝나기 전 검색 요청과 화면의 후보를 함께 확인해 같은 회귀를 막는다.

## 구현 결과

홈은 저장된 기록의 월별 흐름과 대표 작품, 이어가는 작품을 표시한다. 개인 기록이 없으면 빈 타임라인을 보여주며, 실제 공개 글감·인기 작품을 내 기록으로 취급하지 않는다. 타임라인은 기존 서버 커서와 로컬 캐시를 유지한다. 시안의 `data.js`, 가상 기기·계정·반응, Studio 설정은 웹 앱에서 불러오지 않는다.

모바일 중앙 `+`와 PC 기록 버튼은 같은 실제 기록 모달을 연다. 검색은 화면 상단에서 시작하며 `visualViewport`에 맞춰 공간을 조정한다. 시즌·회차·날짜·플랫폼·장소·상황을 기존 API 필드로 저장하고 감상은 3가지 선택지로 표시한다. 숫자 `rating` 계약과 이전 값은 유지한다.

내 공간은 실제 프로필·기기 목록·연결 코드·보관 카드·CSV·기기 해제·데이터 관리 기능을 유지한다. 승인된 아바타와 Pretendard를 로컬 자산으로 제공한다. 리포트·서가·함께 페이지의 실제 데이터 경로를 보존하고 공통 메뉴와 제목 체계를 맞췄다.

날짜 입력은 달력 날짜만 사용한다. 메모만 수정하면 기존 ISO 시각과 오프셋을 그대로 보존한다. 현재 API의 `watchedAt` 필수 계약 때문에 날짜를 완전히 지우는 동작은 추가하지 않았다. API·DB·네이티브 앱은 변경하지 않았다.

### 실제 이미지 확인

TMDB 대표 포스터는 PC의 약 388px 너비에서 DPR 1은 `w500`, DPR 2는 `w780`을 선택한다. 카드·모바일은 더 작은 후보를 사용하며 확대 URL 실패 시 원본, 원본도 실패하면 제목으로 표시한다. 실제 영화·시리즈·책 이미지의 로드와 모바일·PC 표시를 확인했다.

검증한 카카오 책 표지는 API가 제공한 120×174px 이미지였다. URL을 임의 변형하지 않고 `contain`으로 전체 표지를 보여준다. 목록의 PC 84×126px, 모바일 58×87px에서는 표시를 확인했지만 큰 대표 카드나 고밀도 화면에서의 선명도는 제공자의 원본 해상도에 제한된다. 공유 카드에는 별·숫자 없이 감상 문구를 표시하며 `ratingValue`의 기존 요청 계약은 유지한다.

```sh
# apps/web에서, 실행 중인 로컬 웹을 대상으로
WEB_RUNTIME_URL=http://127.0.0.1:4173 V2_QA_BOOK=1 V2_QA_SHARE=1 V2_QA_SERIES=1 node scripts/test-v2-real-data.mjs
WEB_RUNTIME_URL=http://127.0.0.1:4173 node scripts/test-recording-dialog.mjs
TIMELINE_TEST_URL=http://127.0.0.1:4173 node scripts/test-timeline-scroll.mjs
```

호스트에 Playwright 브라우저가 별도로 설치되어 있으면 `PLAYWRIGHT_EXECUTABLE_PATH`로 지정한다. 결과·마스킹된 캡처는 `/tmp/ottline-v2-web-qa`에 두며 Git에 넣지 않는다.

## 현재 실행 구성

### 2026-11-04 인기 작품 포스터 해상도 수정

PC 첫 방문의 ‘요즘 인기 작품’은 카드가 약 299px로 커졌지만 `FirstLogActivationPanel`의 이미지 설정은 기존 `width=116`, TMDB `w185`에 머물러 있었다. 실제 다운로드를 검사하니 Next.js가 128px로 변환한 이미지를 카드 너비까지 확대하고 있었다.

### 2026-11-07 — 사용자가 고른 언어를 메뉴 이동에서도 유지

영어 브라우저로 WSL `http://172.24.75.199:3000`에 접속해 영문 메뉴를 방문한 뒤 KO를 누르면, 본문은 한국어가 되어도 언어 쿠키가 EN으로 돌아가 다음 메뉴가 영어로 열리는 현상을 격리 브라우저에서 재현했다. localhost와 HTTPS ngrok에서는 같은 동선이 유지된다. 실제 프록시에 같은 RSC 요청을 보내도 `Sec-Fetch-Dest`가 없을 때만 `NEXT_LOCALE=en`이 응답에 들어갔다. 설치된 next-intl의 쿠키 보호는 해당 헤더로 백그라운드 요청을 구분하지만 HTTP LAN 브라우저에서는 헤더가 없어 이전 영문 페이지의 재검증을 페이지 방문으로 취급한다.

언어 해석·URL 구조·브라우저 기본 감지는 유지한다. 프록시의 언어 응답에서 문서 탐색 여부를 확인하고, Fetch Metadata가 없는 경우에는 HTML 문서를 요청했는지도 함께 확인해 백그라운드 응답이 선택 쿠키를 바꾸지 않게 한다. 실제 문서 탐색과 KO/EN 버튼의 기존 쿠키 저장은 유지하며, 언어 이외의 쿠키·리다이렉트·rewrite 헤더도 보존한다. API·데이터·동기화·프로필은 변경하지 않는다.

회귀는 실제 프록시의 LAN 백그라운드/문서 요청, 영어 브라우저→KO와 한국어 브라우저→EN, PC·모바일 메뉴 이동·새로고침·새 탭·접두사 없는 진입을 확인한다. 기존 언어 전환·SEO·관리자 접근 경계도 검사한다. [next-intl 언어 협상 문서](https://next-intl.dev/docs/routing/middleware)와 [언어 쿠키 설정 문서](https://next-intl.dev/docs/routing/configuration)는 선택 쿠키와 브라우저 언어의 기존 역할을 확인하는 참고 자료다.

프록시에서 문서 방문 여부를 확인한 뒤, 백그라운드 언어 응답에 포함된 `NEXT_LOCALE`만 제외한다. 쿠키 삭제 응답을 보내 사용자의 선택 자체를 지우지 않으며, `set-cookie`와 내부 `x-middleware-set-cookie`를 함께 정리한 새 응답에 다른 쿠키와 기존 상태·헤더를 유지한다. next-intl 내부 파일이나 패키지는 수정하지 않았다.

검증 완료: Next.js 빌드·타입 검사와 변경 파일 lint(오류 0, 기존 경고 2개), 기존 공유 검사 `canonical-title`을 통과했다. 격리 브라우저의 PC 1440px·모바일 390px에서 새 버튼 문구와 클릭 후 완료·비활성 표시를 확인했으며, 실제 API에는 공유하지 않았다. 개발 3000 반영 후 같은 WSL 동선을 통과했고 고정 ngrok은 HTTP 200이다. 임시 검증 서버는 종료했다. 사용자 교정은 프로젝트 선호에 기록했다.

### 2026-11-08 — 기록 없는 기간의 리포트 카드 공유 제한

기록이 0개인 실제 리포트 화면에 격리 응답을 제공해 주간 공유 버튼이 활성화되는 문제를 재현했다. 버튼이 공유 진행 여부만 검사하고 기간별 기록 수는 검사하지 않는 단일 원인이므로 추가 로그 계측 없이 화면 회귀 검사로 수정한다. 주간·월간·상반기 카드는 각각 지난주·이번 달·상반기 기록이 있을 때만 활성화하고, 클릭 처리에도 같은 조건을 적용한다. 기록 없는 기간에는 ‘이 기간에는 나눌 기록이 없어요.’라고 안내한다. 포스터·장르·메모 유무는 공유 가능 여부에 영향을 주지 않는다.

API·DB·집계 기간·카드 내용은 유지한다. 회귀 검사는 빈 전체 리포트, 예전 기록만 있는 경우, 주간/월간 기록이 각각 또는 모두 있는 경우, 빈/유효 상반기, 로컬 대체 빈 리포트와 한·영 PC·모바일을 확인한다. 비활성 버튼은 카드 생성 요청을 보내지 않고 유효 기간은 기존 공유·저장을 계속 제공하는지 검증한 뒤 개발 3000과 기존 ngrok에 반영한다.

검증 완료: `scripts/test-report-share-availability.mjs`는 수정 전 0개 주간 버튼의 활성 상태를 잡아 실패했고, 수정 후 9개 시나리오를 통과했다. 비활성 기간은 카드 생성 요청이 없고, 기록이 있는 기간은 포스터·장르가 없어도 해당 종류의 카드 요청과 공유를 수행했다. 기존 주간 포스터 payload 검사 1개, Next.js 빌드·타입 검사와 변경 파일 Biome(오류 0, 기존 이미지 경고 1개), diff 공백 검사도 통과했다. 개발 3000에 반영한 뒤 실제 WSL 주소의 한국어 PC 빈 리포트와 영어 모바일 유효 월간 리포트를 다시 확인했다. 고정 ngrok 리포트는 HTTP 200이며 임시 3218 서버는 종료했다. ### 2026-11-08 — 상태 선택과 최종 기록 동작 분리

작품 선택 뒤 모바일 검색창은 844px에서 약 477px로 줄고 아래쪽으로 이동했다. 또한 상태 버튼이 곧 저장이었지만 선택형 입력처럼 보여, 그 아래 ‘그날의 순간’을 채운 뒤 무엇을 눌러야 하는지 불명확했다. `scripts/test-record-save-intent.mjs`로 실제 렌더링과 IndexedDB를 사용해 수정 전 높이 변화부터 실패하는 것을 확인했다.

상태 선택은 임시 선택으로 유지하고, 하단의 ‘기록 남기기’ / ‘Keep this record’를 눌러야 기존 local-first 저장을 수행한다. 일반 검색에서는 상태를 고르기 전 버튼이 비활성화되고 안내가 표시된다. 첫 기록이나 미래의 타임라인에서 사용자가 미리 고른 상태는 선택해 둔 채 열리지만 최종 저장은 여전히 직접 누른다. 메모와 느낌은 필수가 아니며 기존 저장 후 더하기, 공유, 함께 이야기 연결 흐름은 유지한다.

검색·상태·수정 단계는 PC에서 같은 제한 높이, 모바일에서 같은 가시 화면 높이를 사용한다. 상태·수정 단계는 본문만 스크롤하고 하단 액션은 분리해 고정하므로 그날의 순간을 펼치거나 키보드가 올라와도 최종 버튼이 보인다. 상태 선택은 중립색으로 표시하고 주황색은 최종 기록 버튼에 사용한다. 서비스 소개와 기록 가이드도 상태 선택 뒤 최종 버튼을 누르는 흐름으로 고쳤다.

검증: 모바일 한국어 영화(키보드 400px·위치 90px 포함), PC 한국어 영화, 모바일 영어 책, PC 영어 시리즈의 4개 시나리오에서 팝업 높이 유지, 상태 변경·TPO 입력 전후 로컬 기록과 push 0개, 최종 버튼 뒤 기록·push 각각 1개, 시즌·회차·시즌 연도 보존을 확인했다. 기존 함께 이야기 연결 14개, 공개 공유·재시도·오프라인 7개, 추천에서 책 판본을 고른 뒤 미리 선택된 위시리스트를 저장하는 1개 시나리오도 통과했다. 모든 API 요청을 가로채 실제 사용자 데이터를 바꾸지 않았다. 별도 Next.js 빌드와 TypeScript 검사도 통과했다.

개발 3000 반영 뒤 같은 4개 시나리오를 실제 WSL 주소에서도 통과했다. ### 2026-11-08 — 최종 CI의 v2 회귀 검사 연결

Web CI에 날짜·표지·회상·추천·동기화 단위 검사와 명시적 기록 버튼의 브라우저 검사를 연결했다. API CI는 임시 PostgreSQL에서 추천 계정·이야기 연결 검사 17개를 실행하고 건너뛰면 실패하도록 확인한다. 최초 API CI에서 전체 169개, 실패·오류·건너뜀 0개와 기존 데이터의 컨테이너 업데이트 검증을 통과했다.

기존 책 검색 브라우저 검사는 v1 홈의 종류 버튼·숫자 느낌 선택·저장 문구를 찾고 있어 새 검색 팝업·느낌 버튼·명시적 저장과 수정 진입으로 맞췄다. Google 출처, 기존 Kakao 판본, ISBN 없는 책, 오프라인 기록·메모·플랫폼과 서버 정식 ID로의 동기화 보존을 계속 검사한다. 실패한 push 뒤 pull이 끝나기 전 재시도를 보내던 검사 경합은 100ms 지연으로 재현하고, 실제 사용자 재시도 버튼이 활성화되는 실패 완료 상태를 기다리게 고쳤다. 오프라인 수정은 하나의 대기 생성 요청에 메모·느낌·플랫폼이 함께 담기는지 확인하며 세 판본 시나리오와 기존 한국어 플랫폼 보존을 통과했다. 디버그 출력은 제거했다.
